# Uber 골든셋 튜닝 기록

## 평가 목표와 설정 근거

기존 Uber v3 반복 평가의 목표는 **입력과 평가 기준·모델 설정을 고정한 유효 평가 5회에서 평균 통과율 95% 이상**을 확인하는 것이다. 95%는 v1 최초 평가 이후 논의해 현재 v3 반복 검증에 적용한 프로젝트의 작업 기준이며, 최초 평가 전에 정한 목표는 아니다.

LLM 평가에서는 같은 항목의 Pass/Fail이 실행마다 바뀔 수 있다. 매번 100%가 나올 때까지 문장을 수정하면 평가기의 개별 판정에 과도하게 맞출 수 있으므로, 높은 통과 수준을 유지하면서 일부 판정 변동을 관찰할 여지를 두기 위해 95%를 작업 기준으로 삼았다. 외부 표준이나 통계적으로 보장된 경계값은 아니다.

평균 점수만으로 완료를 판단하지 않는다. 배점·필수 구조 오류는 별도로 확인하고, 반복 Fail은 사람이 근거를 검토해 타당한 지적이면 보완한다. 평가 결과 누락·중복 같은 실행 오류는 품질 Fail과 구분해 기록하고, 유효 결과 5개를 확보한다.

## v2 이후에도 평가를 이어간 이유

v2의 세 실행은 100%, 97.53%, 98.77%로 모두 95%를 넘었다. 따라서 점수 자체만 보면 v2에서 튜닝을 멈추고 기준본으로 삼는 선택도 가능했다. 이후 작업은 100%를 매번 얻기 위한 점수 올리기가 아니라, 반복 지적과 판정 안정성을 확인하는 후속 실험으로 구분한다.

- Middle C2의 3-6이 서술형 두 실행에서 연속 Fail이었다. 쓰기 부하를 줄이는 3점 기준이 검색 지연 목표와 충분히 연결되는지 검토할 필요가 있었다.
- v2 세 실행에는 질문형 1회와 서술형 2회가 섞여 있었다. 입력을 고정한 동일 조건의 반복 평가와 구분해야 했다.
- 이에 Middle C2의 3점을 검색 후보 수 제한으로 보완하고, Senior 2점에는 관련 문제의 기본 대응을 남기면서 3점의 대안 검토·동적 조절·Trade-off와 구별한 v3를 고정해 유효 5회 평가한다.

v2가 95% 미달이어서 다시 평가한 것은 아니다. 수정한 채점 내용의 정합성과 반복 평가의 일관성을 확인하기 위해 진행했다. 이 결과만으로 다른 주제에 대한 일반화 성능을 주장하지 않는다.

v1의 실패 7건을 분석해 NFR 요구 수준과 Senior의 단계별 채점 기준을 수정했다. 사용자가 제공한 v2 세 실행의 통과율은 100%, 97.53%, 98.77%다. 초기 실패 7건은 세 실행 모두 Pass였으며, 후속 실행에서는 다른 항목의 실패가 관찰됐다. 아래에 수정 전후 문장과 실행별 결과를 기록한다.

두 골든 문서·평가 기준·연차 기준의 해시가 이전 실행과 일치한다. 평가 함수와 결과 스키마도 구문 트리 기준으로 동일하다. 폴더 이동으로 입력 파일 경로는 달라졌다. 실행 시점·반복 횟수와 모델 응답의 변동이 있으므로 차이 전부를 reasoning 설정의 효과라고 단정하지 않는다.

### low와 high의 차이

이전 low 유효 5회는 평균 100.00%(405/405 Pass)였다. 이번 high는 유효 3회·오류 0회이며, 평균 통과율은 **98.77%**, 이전 평균 대비 **-1.23%p**다. high 유효 회차 사이에 판정이 달라진 조합은 0개다.

- **uber_middle C3 · 3-4**: 이전 low는 5/5회 Pass, 이번 high는 3/3회 Fail.

  1회차 적용 기준: 제시된 방식만으로 명시한 장애 상황의 중복 효과를 막을 수 없다면 실패다.

  판단 근거: 3점은 ‘완료 기록 전에 종료’되는 상황에 ‘이미 완료된 요청인지 확인’하는 방안만 제시한다. 효과가 발생한 뒤 완료 기록이 남기 전에 중단되면 이 확인만으로는 이미 실행된 요청을 식별할 수 없어 중복 처리를 막기에 부족하다.

  2회차 적용 기준: 명시한 장애 구간에서 중복 효과를 막을 수 있는 처리 조건을 요구해야 한다.

  판단 근거: 3점은 ‘완료 기록 전에 종료’되는 상황을 제시하면서 재처리 시 완료 여부 확인만 요구한다. 결과는 반영됐지만 완료 기록이 없는 경우에 중복 효과를 막을 조건이 없어, 제시된 확인만으로는 해당 장애 구간을 해결하지 못한다.

  3회차 적용 기준: 제시한 재처리 방식이 해당 장애 구간에서 중복 효과를 방지할 수 있어야 한다.

  판단 근거: 처리 효과가 발생했지만 ‘완료 기록 전에 종료’된 경우에는 ‘이미 완료된 요청인지 확인’하는 것만으로 중복 실행을 막지 못한다. 처리 결과와 완료 상태를 함께 기록하거나 호출별 멱등 처리를 요구하는 조건이 없어 제시한 장애 구간을 해결하지 못한다.

새 Fail은 사람의 검토가 필요한 평가기 지적이다. 통과율 하락만으로 high의 정확성이 더 높거나 골든셋의 품질이 나빠졌다고 판단하지 않는다. 이번 실행에서 골든셋이나 평가기를 수정하지 않았다.
