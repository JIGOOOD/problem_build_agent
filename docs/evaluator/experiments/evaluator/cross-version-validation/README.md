# 평가기 튜닝 전·1~4차의 동일 검증셋 3회 비교

## 문제

튜닝 데이터에서 얻은 개선 수치만으로 새로운 사례의 오류 검출 능력을 판단할 수는 없다. 동일한 검증 데이터에서 튜닝 전과 각 수정 버전을 비교하고, 한 번의 평가에서 나온 수치가 반복되는지도 확인했다.

## 단계별 수정과 이유

생성물은 고정하고 다음 평가 기준 버전을 비교했다. 이 반복 검증 중에는 평가 기준·연차 기준·정답표를 수정하지 않았다.

| 버전 | 발견한 문제 | 수정한 내용과 이유 |
|---|---|---|
| 튜닝 전 | 연차와 전체적인 깊이를 포괄적으로 판단 | 기존 기준선. 이후 수정의 비교 대상으로 사용 |
| 1차 | 점수별 부족·과도한 요구를 놓침 | 3-5를 연차·Level별 표와 구체적인 Fail 조건으로 바꿔 각 점수가 요구하는 역량을 판단 |
| 2차 | 개별 오류를 지적해도 연차 차이는 통과시킴 | 4-1에서 같은 설계 문제를 대응시키고 처리 원리·문제 대응·설계 판단의 차이를 비교 |
| 3차 | 다른 점수나 항목의 장점이 차이 부족을 가림 | 2점·3점을 각각 비교하고, 다른 Level·Criterion의 장점으로 부족을 상쇄하지 않도록 명시 |
| 4차 | Middle의 과도한 요구와 Senior의 미완성 기본 흐름을 놓침 | Middle의 독립적인 추가 대응 범위를 확인하고, Senior 1점의 처리 대상·방식·결과 연결을 요구. 정상 기본 흐름에 상세 메커니즘까지 요구하지 않는 경계도 명시 |

## 검증 방식

- Dropbox·Slack·YouTube·Uber 각 1쌍과 오류 주입 4쌍으로 총 8쌍·16개 루브릭을 사용했다.
- 1회당 3-5 Criterion 64개와 4-1 비교 8개, 총 72항목이다. 제공 정답표는 Fail 25항목·Pass 47항목이다.
- 각 버전을 3회씩 평가했다. 당시 공통 연차 기준과 gpt-6.1-sol/high를 고정하고, 3-5·4-1의 단계별 평가 기준만 바꿨다.
- 모든 버전·회차에서 같은 루브릭 원문과 정답표를 사용했다. 정답표는 모델에 보내지 않고 사후 집계에만 사용했다.

## 결과 해석과 남은 문제

튜닝 전에서 4차까지 합산 TPR은 **42.67%→78.67%**, TNR은 **100.00%→92.20%**였다. 최종 4차의 반복 판정에서 오류 16건을 놓쳤고, 정상 11건을 Fail로 지적했다. 오류 검출과 정상 항목 오탐을 함께 확인해야 한다.

4-1 연차 비교만 분리하면 오류 검출률은 **0.00%→75.00%**였다. 항목별 집계는 상세 결과의 `pooled_by_rule`에 포함했다.

3회 합산은 같은 사례에 대한 반복 판정 결과다. 표본이 3배 늘어난 독립 검증으로 해석하지 않는다. 또한 이 결과는 Criterion·비교 쌍의 Pass/Fail 정확성이며, 틀린 Level이나 오류 원인까지 정확히 지적했는지는 별도다.

1회차는 당시 완료된 실제 실행의 집계만 남아 있어 항목별 근거를 재검토할 수 없다. 2·3회차의 정답 불일치와 실제 판단 근거는 상세 결과에 포함했다.

## 계산 기준

Fail을 양성으로 두었다. TP는 실제 오류 검출, FN은 오류 누락, TN은 정상 판정, FP는 정상 항목 오탐이다.

- TPR = TP / (TP + FN)
- TNR = TN / (TN + FP)
- Precision = TP / (TP + FP)
- 판정 정확도 = (TP + TN) / 전체 판정 수
