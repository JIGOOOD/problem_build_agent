# 평가기 검증 다른 주제의 오류 검출과 정상 수용

## 문제

튜닝에 사용한 오류 주입·티켓에서 얻은 결과가 다른 주제에서도 유지되는지 확인할 필요가 있었다. 오류를 잡는 것뿐 아니라 정상적인 기본 설계를 불필요하게 탈락시키는지도 함께 확인했다.

## 적용

4차 평가 기준과 프로젝트 연차 기준을 고정하고 Dropbox·Slack·YouTube·Uber 각 한 쌍, 검증 오류 주입 네 쌍에 적용했다. 검증 중 평가기를 추가로 수정하지 않았다.

Uber는 사용자가 확인한 전체 Pass 정답을 적용했다. 실제 평가기의 Fail을 정상 판정으로 바꾸지 않고 오탐으로 집계했다.

## 평가 결과

| 측정 항목 | Dropbox · 1쌍 | Slack · 1쌍 | YouTube · 1쌍 | Uber · 1쌍 | 오류 주입 · 4쌍 | 검증 합산 · 8쌍 |
|---|---|---|---|---|---|---|
| 직접 오류 원인 검출률 | 33.33% · 1/3 | 33.33% · 2/6 | 해당 없음 | 해당 없음 | 100% · 12/12 | 71.43% · 15/21 |
| 연차 비교 오류 검출률 · 4-1 | 100% · 1/1 | 0% · 0/1 | 해당 없음 | 해당 없음 | 100% · 2/2 | 75% · 3/4 |
| 정상 항목 통과율 | 60% · 3/5 | 100% · 2/2 | 100% · 9/9 | 88.89% · 8/9 | 100% · 22/22 | 93.62% · 44/47 |
| 전체 판정 일치율 | 66.67% · 6/9 | 44.44% · 4/9 | 100% · 9/9 | 88.89% · 8/9 | 100% · 36/36 | 87.5% · 63/72 |

검증 오류 주입의 직접 오류는 12/12를 검출했지만, Dropbox·Slack의 직접 오류는 합계 3/9만 검출했다. 명시적인 주입 오류와 실제 문장의 요구 범위·기본 흐름 경계를 다르게 처리하는 문제가 남았다.

## 남은 문제

- **Dropbox:** Middle C4 2점의 과도한 범위를 놓쳤다. Senior C3은 Fail이지만, 정답의 부하 집계·분산 경로 부족과 다른 변경 추적 연결을 지적해 직접 검출로 세지 않았다.
- **Slack:** Middle C1·C2·C4 2점의 과도한 범위와 Senior C3 1점의 지연 측정 대상 부족을 놓쳤다. 연차 차이가 부족하다는 4-1 정답도 Pass 처리했다.
- **정상 항목 오탐:** Dropbox Senior C2·C4와 Uber Senior C3을 Fail 처리했다. 정상 항목 수용은 44/47이었다.
- **YouTube:** 아홉 판정 모두 제공 정답과 일치했다.

직접 오류 검출은 실제 판단 근거가 정답표의 오류 원인을 지적했는지 대조한 비율이다. 전체 판정 일치율은 Criterion·비교 쌍의 Pass/Fail이 정답과 같은 비율이며, 올바른 원인까지 찾았다는 뜻은 아니다.
