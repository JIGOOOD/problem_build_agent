# 티켓 생성기 기준선

## 문제

Middle 2점이 기본 흐름 이상의 여러 문제 대응과 검증을 필수화했다. Senior 1점은 기본 설계라는 선언만으로 충족될 수 있었고, 일부 항목은 두 연차의 2점 요구가 사실상 같았다.

## 수정

수정 없이 기존 생성 프롬프트로 Middle·Senior를 생성해 튜닝 전 상태를 측정했다.

## 평가 결과

| 측정 항목 | 기준선 결과 |
|---|---|
| Middle 연차 적합성 통과율 · 3-5 | 50% · 2/4 |
| Senior 연차 적합성 통과율 · 3-5 | 0% · 0/4 |
| 연차 간 역량 차이 통과율 · 4-1 | 0% · 0/1 |
| 전체 통과율 | 22.22% · 2/9 |

항목별 판정은 다음과 같다.

| 평가 기준·대상 | Middle | Senior | 두 연차 비교 · 한 쌍 |
|---|---|---|---|
| 3-5 · C1 | Pass | Fail | — |
| 3-5 · C2 | Fail | Fail | — |
| 3-5 · C3 | Pass | Fail | — |
| 3-5 · C4 | Fail | Fail | — |
| 3-5 합계 | 2/4 | 0/4 | — |
| 4-1 · 실질적인 역량 차이 | — | — | Fail · 0/1 |

## 남은 문제

- **Middle C2:** 2점에 기본 복구 외에도 중복 방지와 불확실한 결제 결과의 대사를 함께 필수화해 범위가 과도하다.
- **Middle C4:** 2점에 잔여 병목 분석과 추가 자원의 효과 검증까지 요구한다.
- **Senior C1:** 1점에서 점유·만료와 결제 결과 반영의 기본 상태 전이가 연결되지 않는다.
- **Senior C2:** 1점에서 접수 전 보존할 상태와 중단 후 복구할 작업이 연결되지 않는다.
- **Senior C3:** 1점에서 유입 제어가 접수 작업의 처리 보호로 이어지는 흐름이 부족하다.
- **Senior C4:** 1점이 공연별 분산만으로 충족될 수 있어 인기 공연 내부의 확장을 보장하지 않는다.
- **4-1 연차 비교:** C2·C4의 두 연차 2점 요구가 사실상 같아 Senior의 추가 역량이 구분되지 않는다.
