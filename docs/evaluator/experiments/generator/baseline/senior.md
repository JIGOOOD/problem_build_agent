# 공연 좌석 티켓 예매

**설계 범위**
공연별 좌석 잔여 현황 조회, 좌석 임시 점유와 만료, 주문 생성과 외부 결제 결과에 따른 예매 확정 또는 해제까지 설계한다. 결제 대행사 내부 구현·환불·재판매·공연 추천은 제외한다.

**평가 초점**
동일 좌석의 중복 예매 방지, 점유 만료·지연 결제 응답·재시도의 상태 일관성, 예매 오픈 시 조회·점유 요청 폭증 대응, 접수된 주문의 장애 후 복구와 중복 확정 방지

**대상 연차** Senior\
**배점** 100

## NFR-1. Consistency

**요구 수준**
`consistency` — 동시 요청에서도 같은 좌석에 서로 충돌하는 점유나 예매를 성공시키지 않는다. 지연 결제 응답과 오래된 만료 작업은 현재 소유권과 확정 상태를 덮어쓰지 않는다. 조회에 보인 잔여 좌석은 점유 성공을 보장하지 않으며, 실제 점유·확정 시 유효성을 판정한다.
동일 공연의 동일 좌석에는 유효한 점유 소유자와 확정 예매가 충돌하지 않아야 하며, 점유·만료·결제 결과·재시도의 경합에서도 허용된 상태 전이만 반영되어야 한다.

### C1. 좌석 소유권과 상태 전이의 정합성 · 30

**평가 항목**
좌석 조회부터 점유·만료·결제 결과 반영까지 동일 좌석의 소유권과 상태 변경을 판정하는 경계를 평가하며, 장애 후 주문 복구 절차는 제외한다.

| Level | 기준 |
|---|---|
| 0 | 동일 좌석에 대한 동시 점유와 만료·결제 결과의 충돌을 고려하지 않고, 요청마다 독립적으로 좌석 상태를 변경한다. |
| 1 | 중복 점유를 막는 기본 설계와 점유 만료를 제시하지만, 소유권·유효성 확인과 상태 변경의 원자적 경계 또는 만료와 결제 응답의 경합 처리 방안을 구체적으로 설명하지 못한다. |
| 2 | 조회 결과와 실제 점유 판정을 구분하고, 소유권·유효성을 검증하는 원자적 상태 변경을 설명한다. 만료·지연 결제·재시도가 경합해도 선택한 정책에 따라 처리하며, 오래된 요청이 현재 소유권이나 확정을 덮어쓰지 않게 한다. |
| 3 | 2점에 더해, 만료 후 재할당과 이전 결제 응답이 겹치는 상황으로 설계의 한계를 분석한다. 점유 연장 여부 등 선택한 경합 정책의 장단점을 비교하고, 중복 판매 없이 결과를 추적하도록 보완하는 근거를 설명한다. |

## NFR-2. Fault Tolerance

**요구 수준**
`fault_tolerance` — 주문 접수를 성공으로 응답한 뒤 처리 프로세스가 중단되어도 주문과 처리 진행 상태를 복구할 수 있다. 동일 요청이나 결제 이벤트를 다시 처리해도 예매 확정 효과는 중복되지 않는다. 결제 결과를 받지 못했거나 점유 만료와 충돌한 주문은 확인 가능한 미결 상태로 남겨 외부 상태와 대사하며, 이미 재할당된 좌석을 중복 확정하지 않는다.
접수한 주문은 처리 중 장애와 외부 결제 결과의 유실·중복 전달 이후에도 복구 가능해야 하며, 복구와 재시도가 중복 주문 효과나 중복 예매 확정을 만들지 않아야 한다.

### C2. 접수 주문의 복구와 중복 효과 방지 · 25

**평가 항목**
주문 접수 성공 이후 장애와 결제 결과 유실·중복에 대비한 지속성·재처리·대사 흐름을 평가하며, 좌석 상태 전이 자체의 동시성 판정은 제외한다.

| Level | 기준 |
|---|---|
| 0 | 접수 성공 이후 처리 중단이나 결제 결과 유실·중복을 고려하지 않고, 정상 요청의 완료 흐름만 제시한다. |
| 1 | 주문 저장과 재시도로 복구하는 기본 설계를 제시하지만, 접수 성공의 지속성 경계나 재처리 대상 식별, 중복 확정 방지 또는 미결 결제 확인 방법을 구체적으로 설명하지 못한다. |
| 2 | 성공 응답 전에 주문과 복구에 필요한 진행 정보를 지속시키는 경계를 설명한다. 중단된 작업의 재개와 중복 효과 방지 메커니즘을 제시하고, 결제 결과 유실·만료 충돌은 미결로 추적하여 외부 상태와 대사한다. |
| 3 | 2점에 더해, 재처리 도중 재장애나 대사와 중복 결제 알림의 경합에서 완료 판단이 어긋날 수 있는 지점을 분석한다. 재처리 기준과 완료 기록을 보완하고, 복구 지연과 외부 확인 부담 등 선택의 장단점과 근거를 설명한다. |

## NFR-3. High Throughput

**요구 수준**
`throughput` — 검증된 처리 능력에 맞추어 유입을 제어하고, 초과 요청은 대기 또는 명시적인 제한 응답으로 처리한다. 요청 폭증이 내부 작업의 무제한 적체나 전체 처리 실패로 이어지지 않도록 하며, 이미 진입한 요청의 처리를 지속할 수 있어야 한다. 구체적인 처리량과 동시 사용자 한도는 부하 검증으로 정한다.
예매 오픈 시 요청 유입이 처리 능력을 넘더라도 실제 처리 경로에 전달되는 부하를 제어하여, 접수한 조회·점유·주문 처리가 과부하로 함께 붕괴하지 않아야 한다.

### C3. 처리 능력에 맞춘 유입과 적체 제어 · 25

**평가 항목**
예매 오픈 시 조회·점유·주문 경로의 유입 제한과 내부 적체 제어로 접수된 처리를 보호하는 판단을 평가하며, 자원 추가를 통한 처리 범위 확대는 제외한다.

| Level | 기준 |
|---|---|
| 0 | 요청 유입이 처리 능력을 초과하는 상황을 고려하지 않고, 모든 요청을 제한 없이 내부 처리 경로에 전달한다. |
| 1 | 초과 요청의 대기나 제한 응답을 제시하지만, 제한 기준을 처리 능력과 연결하지 못하거나 내부 적체와 이미 접수된 작업을 보호하는 구체적인 흐름을 설명하지 못한다. |
| 2 | 부하 검증으로 수용 한계를 정하고 유입을 제어하는 메커니즘을 설명한다. 초과 요청의 처리 방식과 내부 적체의 제한 경계를 제시하며, 병목 경로로 부하가 전파되어 접수된 조회·점유·주문 처리가 함께 멈추지 않도록 한다. |
| 3 | 2점에 더해, 처리 능력 변화나 제한 응답 이후 재시도 집중으로 제어가 늦어지는 한계를 분석한다. 관측한 적체와 처리 상태를 바탕으로 제어를 보완하고, 수용률과 접수 작업 보호 사이의 선택 근거를 설명한다. |

## NFR-4. Scalability

**요구 수준**
`scalability` — 공연 수와 요청량 증가에 따라 처리 자원을 추가해 수용 범위를 넓힐 수 있어야 한다. 인기 공연에 부하가 집중되는 경우에도 추가 자원이 효과를 내는 분산 단위와 남는 병목을 설명하고 검증할 수 있어야 한다. 동일 좌석의 충돌 판정을 병렬화한다는 이유로 정합성을 약화하지 않는다.
조회·점유 부하가 증가할 때 자원과 처리 범위를 확장할 수 있어야 하며, 특정 인기 공연에 집중된 부하가 하나의 고정된 처리 단위에만 묶이지 않도록 해야 한다.

### C4. 인기 공연 집중 부하의 확장 경계 · 20

**평가 항목**
조회·점유 부하 증가에 따른 자원 확장과 인기 공연 내부의 분산 단위·잔여 병목을 평가하며, 초과 요청의 입장 제한 정책은 제외한다.

| Level | 기준 |
|---|---|
| 0 | 공연 수와 조회·점유 요청량 증가에 따른 확장이나 특정 인기 공연에 부하가 집중되는 문제를 고려하지 않는다. |
| 1 | 처리 자원 추가나 공연별 분산의 기본 설계를 제시하지만, 인기 공연 내부에서 추가 자원이 효과를 내는 단위와 공유 병목을 구체적으로 설명하지 못한다. |
| 2 | 조회·점유의 접근 패턴에 맞춘 분산 단위와 자원 확장 메커니즘을 설명한다. 인기 공연 내부에도 부하를 분산하면서 동일 좌석의 충돌 판정을 유지하고, 남는 병목과 추가 자원의 효과를 부하 검증으로 확인하는 방법을 제시한다. |
| 3 | 2점에 더해, 분산 후에도 특정 좌석이나 공유 경로에 집중되는 부하로 확장 효과가 제한되는 상황을 분석한다. 병목 완화 방안과 남는 한계를 제시하고, 분산 세분화에 따른 조회·조정 복잡성 등 선택의 장단점과 근거를 설명한다. |
