# 공연 좌석 티켓 예매

**설계 범위**
공연별 좌석 잔여 현황 조회, 좌석 임시 점유와 만료, 주문 생성과 외부 결제 결과에 따른 예매 확정 또는 해제까지 설계한다. 결제 대행사 내부 구현·환불·재판매·공연 추천은 제외한다.

**평가 초점**
동일 좌석의 중복 예매 방지, 점유 만료·지연 결제 응답·재시도의 상태 일관성, 예매 오픈 시 조회·점유 요청 폭증 대응, 접수된 주문의 장애 후 복구와 중복 확정 방지

**대상 연차** Senior\
**배점** 100

## NFR-1. Consistency

**요구 수준**
`consistency` — 동시 점유·확정 요청 중 유효한 좌석 권리를 얻는 요청만 성공한다. 합의된 시간 기준과 만료 경계에 따라 확정 또는 만료의 승자를 결정하며, 이전 점유의 만료 작업이나 지연 결제 결과는 새 점유·확정을 변경하지 않는다. 잔여 현황 조회에 지연을 허용하더라도 점유·확정 성공은 권위 있는 현재 상태로 판정한다.
같은 공연의 동일 좌석에 유효한 점유나 확정 예매가 중복 성립하지 않아야 하며, 만료 처리와 지연 결제 결과가 경합하더라도 이미 바뀐 좌석 소유 상태를 과거 요청이 덮어쓰지 않아야 한다.

### C1. 좌석 권리의 유일성과 상태 전이 · 30

**평가 항목**
좌석 점유·만료·확정의 정상 처리와 경합에서 현재 권리를 판정하고 과거 요청의 덮어쓰기를 차단하는 설계를 평가하며, 장애 후 주문 복구는 제외한다.

| Level | 기준 |
|---|---|
| 0 | 동일 좌석의 중복 점유·확정이나 만료·지연 결제 결과에 의한 좌석 소유 상태 변경 문제를 고려하지 않는다. |
| 1 | 현재 좌석 상태를 확인해 점유하고 결제 결과에 따라 확정·해제하며 만료 시 반환하는 흐름을 설명한다. 다만 동시 요청의 승자 결정이나 과거 점유 요청 차단을 구체화하지 못한다. |
| 2 | 권위 있는 상태에서 유효성 검사와 변경이 원자적으로 귀결되는 메커니즘을 설명한다. 시간 기준과 만료 경계를 정하고 점유 식별 등으로 만료·지연 결과가 새 권리를 바꾸지 못하게 하며, 조회 지연과 배정 판정을 구분한다. |
| 3 | 2점 설계에서 동일 좌석 변경의 직렬화나 충돌 재시도가 만드는 한계를 분석한다. 정확성 경계를 유지하면서 임계 구간 축소 등 대응을 제시하고, 대기·재시도 비용과 선택 근거를 설명한다. |

## NFR-2. Fault Tolerance

**요구 수준**
`fault_tolerance` — 접수 완료한 주문은 장애 후 식별하여 처리를 재개할 수 있고, 결과가 불명확한 결제 시도는 외부 결과와 대사할 수 있다. 동일 요청과 결제 이벤트의 재처리는 추가 주문이나 중복 확정·해제를 만들지 않는다. 만료 후 도착한 결제 성공도 현재 좌석 권리를 침해하지 않으며, 미해결 상태를 추적할 수 있어야 한다.
접수한 주문과 결제 시도의 처리 상태를 장애 후 복구할 수 있어야 하며, 요청 재시도와 결제 결과의 중복·지연 전달에도 동일 주문의 확정 또는 해제가 중복 반영되지 않아야 한다.

### C2. 접수 주문의 복구와 재처리 안전성 · 30

**평가 항목**
접수 완료한 주문과 결제 시도의 장애 후 재개·대사 및 중복 반영 방지를 평가하며, 좌석 권리 판정 자체보다 복구 작업의 진행과 완료 기록을 다룬다.

| Level | 기준 |
|---|---|
| 0 | 주문 접수 후 장애로 처리가 중단되거나 요청·결제 결과가 다시 전달될 때 주문을 복구하고 중복 반영을 막는 문제를 고려하지 않는다. |
| 1 | 주문과 결제 시도를 보존하고 미완료 건을 찾아 외부 결과를 확인한 뒤 확정·해제를 재개하는 흐름을 설명한다. 재처리 시 기존 결과를 확인하지만, 중복 실행이나 처리 도중 장애에 대한 구체적 방안은 부족하다. |
| 2 | 접수 완료 전 복구 가능한 상태를 남기고, 식별자를 통해 불명확한 결제 결과를 대사한다. 중복 실행과 반영·완료 기록 사이의 장애에도 추가 주문이나 중복 확정·해제가 없도록 설명하며, 만료 후 성공은 현재 권리를 침해하지 않고 추적한다. |
| 3 | 2점 설계에서 자동 재시도와 복구 작업의 중첩이나 외부 결과 확인의 장기 실패가 남기는 한계를 분석한다. 미해결 건의 재점검·처리 인계 등 개선을 제시하고, 복구 진행성과 중복 방지 사이의 선택 근거를 설명한다. |

## NFR-3. High Throughput

**요구 수준**
`throughput` — 조회·점유 요청의 유입을 처리 용량 이상으로 높이는 부하 시험에서도, 수락한 요청의 유효 완료량이 과부하와 재시도 증폭 때문에 급격히 붕괴하지 않아야 한다. 초과 요청은 통제 가능한 대기나 거절 등으로 다루고, 접수 완료한 주문의 복구 책임과 접수 전 유입 제한을 구분한다.
예매 오픈 시 조회·점유 요청이 처리 용량을 초과하더라도 과부하와 재시도 증폭으로 유효 처리량이 붕괴하지 않도록 해야 한다.

### C3. 용량 초과 시 유효 처리량 유지 · 20

**평가 항목**
예매 오픈 시 조회·점유 요청이 현재 처리 용량을 초과할 때 유입·적체·재시도를 제어하는 설계를 평가하며, 자원 증설에 따른 확장성은 제외한다.

| Level | 기준 |
|---|---|
| 0 | 처리 용량을 넘는 조회·점유 요청이나 재시도 증폭으로 수락한 요청의 완료량이 붕괴하는 문제를 고려하지 않는다. |
| 1 | 조회·점유 요청을 수락하거나 대기·거절로 분기하고 수락한 요청을 처리하는 흐름을 설명한다. 다만 적체 한계나 재시도 제어, 하위 의존성의 용량을 구체적으로 연결하지 못한다. |
| 2 | 병목 용량에 맞춰 유입과 대기를 제한하고 재시도 증폭을 억제하는 메커니즘을 설명한다. 접수 전 제한과 접수 주문의 복구 책임을 구분하며, 용량 초과 부하 시험에서 수락 요청의 유효 완료량과 적체를 확인하는 방법을 제시한다. |
| 3 | 2점 설계에서 의존성 용량 변화나 제한 지점에 도달하기 전의 자원 소모가 보호 효과를 약화시키는 상황을 분석한다. 제어 위치·기준의 개선과 검증 방법을 제시하고, 요청 거절·대기와 유효 완료량 사이의 선택 근거를 설명한다. |

## NFR-4. Scalability

**요구 수준**
`scalability` — 특정 공연에 요청이 집중되는 조건에서도 처리 자원과 작업 분담을 늘려 처리 가능한 범위를 확대할 수 있어야 한다. 동일 좌석의 배정 경합처럼 병렬화할 수 없는 한계는 구분하고, 공연 전체 조회와 개별 좌석 점유 각각의 확장 병목을 설명할 수 있어야 한다. 선형 확장이나 특정 분할 기술은 요구하지 않는다.
요청량이 증가할 때 자원과 처리 분담을 늘려 조회·점유 처리 범위를 확장할 수 있어야 하며, 특정 공연에 대한 집중 부하가 하나의 분할 단위에 고착되지 않도록 해야 한다.

### C4. 집중 부하의 작업 분담과 확장 · 20

**평가 항목**
특정 공연에 집중되는 전체 좌석 조회와 개별 좌석 점유를 자원 추가와 작업 분담으로 확장하는 설계를 평가하며, 고정 용량에서의 초과 유입 제한은 제외한다.

| Level | 기준 |
|---|---|
| 0 | 조회·점유 요청의 증가에 따른 작업 분담이나 특정 공연의 부하가 하나의 처리 단위에 집중되는 문제를 고려하지 않는다. |
| 1 | 조회와 점유의 처리 주체를 나누고 자원을 추가해 요청을 분담하는 기본 흐름을 설명한다. 다만 같은 공연의 요청이 늘 때 저장소나 특정 처리 단위에 남는 집중 병목을 해결하지 못한다. |
| 2 | 특정 공연 내부의 작업도 여러 자원에 분담하는 구체적 경로를 설명한다. 전체 좌석 조회의 취합과 개별 좌석 점유의 병목을 각각 다루며, 자원 추가로 늘어나는 처리 범위와 동일 좌석 경합의 병렬화 한계를 구분한다. |
| 3 | 2점 설계에서 분담을 늘릴수록 커지는 조회 취합 비용이나 남는 부하 편중을 분석한다. 분담 단위·조회 경로의 개선을 제시하고, 병렬 처리 이득과 취합·조정 부담 사이의 선택 근거를 설명한다. |
