# 공연 좌석 티켓 예매

**설계 범위**
공연별 좌석 잔여 현황 조회, 좌석 임시 점유와 만료, 주문 생성과 외부 결제 결과에 따른 예매 확정 또는 해제까지 설계한다. 결제 대행사 내부 구현·환불·재판매·공연 추천은 제외한다.

**평가 초점**
동일 좌석의 중복 예매 방지, 점유 만료·지연 결제 응답·재시도의 상태 일관성, 예매 오픈 시 조회·점유 요청 폭증 대응, 접수된 주문의 장애 후 복구와 중복 확정 방지

**대상 연차** Middle\
**배점** 100

## NFR-1. Consistency

**요구 수준**
`consistency` — 동시 점유·확정 요청 중 유효한 좌석 권리를 얻는 요청만 성공한다. 합의된 시간 기준과 만료 경계에 따라 확정 또는 만료의 승자를 결정하며, 이전 점유의 만료 작업이나 지연 결제 결과는 새 점유·확정을 변경하지 않는다. 잔여 현황 조회에 지연을 허용하더라도 점유·확정 성공은 권위 있는 현재 상태로 판정한다.
같은 공연의 동일 좌석에 유효한 점유나 확정 예매가 중복 성립하지 않아야 하며, 만료 처리와 지연 결제 결과가 경합하더라도 이미 바뀐 좌석 소유 상태를 과거 요청이 덮어쓰지 않아야 한다.

### C1. 좌석 권리의 유일성과 상태 전이 · 30

**평가 항목**
동일 공연·좌석의 점유부터 만료·확정·해제까지 좌석 권리를 판정하는 흐름을 평가하며, 장애 후 주문 복구가 아닌 현재 권리의 유일성과 과거 요청의 상태 덮어쓰기 방지를 다룬다.

| Level | 기준 |
|---|---|
| 0 | 같은 좌석에 여러 점유나 확정이 성립할 수 있는 문제를 고려하지 않고, 조회 결과만으로 좌석 배정 성공을 결정한다. |
| 1 | 중복 배정 문제를 인식하고 잠금이나 상태 검사 등의 방안을 제시하지만, 점유·만료·확정을 담당하는 구성요소와 권리 확인 후 변경되는 흐름을 충분히 연결하지 못한다. |
| 2 | 권위 있는 좌석 상태에서 유효성 확인과 변경을 하나의 결과로 처리해 중복 권리를 막는 구성을 설명한다. 점유 소유자와 만료 시간의 판단 기준을 정하고, 조회 지연과 구분하여 점유·만료·결제 결과에 따른 기본 전이를 설명한다. |
| 3 | 2점 설계에 더해, 만료와 확정의 경합이나 이전 점유의 지연 결과가 새 권리를 덮어쓰는 한계를 설명한다. 점유 식별과 현재 상태의 조건부 확인 등 동등한 방법으로 승자를 정하고 오래된 변경을 무효화하는 개선을 제시한다. |

## NFR-2. Fault Tolerance

**요구 수준**
`fault_tolerance` — 접수 완료한 주문은 장애 후 식별하여 처리를 재개할 수 있고, 결과가 불명확한 결제 시도는 외부 결과와 대사할 수 있다. 동일 요청과 결제 이벤트의 재처리는 추가 주문이나 중복 확정·해제를 만들지 않는다. 만료 후 도착한 결제 성공도 현재 좌석 권리를 침해하지 않으며, 미해결 상태를 추적할 수 있어야 한다.
접수한 주문과 결제 시도의 처리 상태를 장애 후 복구할 수 있어야 하며, 요청 재시도와 결제 결과의 중복·지연 전달에도 동일 주문의 확정 또는 해제가 중복 반영되지 않아야 한다.

### C2. 접수 주문의 복구와 중복 반영 방지 · 25

**평가 항목**
접수 완료한 주문과 결제 시도의 장애 후 처리 재개·결과 대사·중복 반영 방지를 평가하며, 좌석 권리 판정 자체나 금전 반환 절차는 채점 범위에서 제외한다.

| Level | 기준 |
|---|---|
| 0 | 주문 접수 후 장애로 처리 상태가 사라지거나 요청·결제 결과의 재전달로 확정·해제가 중복 반영되는 문제를 고려하지 않는다. |
| 1 | 주문 보존이나 재시도의 필요성을 인식하고 저장·재처리를 제안하지만, 미완료 주문을 찾고 결제 결과와 연결하여 처리를 재개하는 흐름을 충분히 설명하지 못한다. |
| 2 | 접수한 주문과 결제 시도의 식별·상태를 보존하고, 복구 담당 구성요소가 미완료 건을 찾아 외부 결과와 대사하는 흐름을 설명한다. 동일 요청·이벤트를 식별해 추가 주문과 중복 반영을 막고, 미해결 건을 추적하는 기본 동작을 제시한다. |
| 3 | 2점 설계에 더해, 외부 결제 요청 후 결과 저장 전 장애나 재처리 도중 장애로 남는 불확실성을 설명한다. 기록된 처리 단계와 외부 결과를 재확인해 안전하게 재개하고, 만료 후 성공 결과도 현재 좌석 권리 판정에 연결하는 개선을 제시한다. |

## NFR-3. High Throughput

**요구 수준**
`throughput` — 조회·점유 요청의 유입을 처리 용량 이상으로 높이는 부하 시험에서도, 수락한 요청의 유효 완료량이 과부하와 재시도 증폭 때문에 급격히 붕괴하지 않아야 한다. 초과 요청은 통제 가능한 대기나 거절 등으로 다루고, 접수 완료한 주문의 복구 책임과 접수 전 유입 제한을 구분한다.
예매 오픈 시 조회·점유 요청이 처리 용량을 초과하더라도 과부하와 재시도 증폭으로 유효 처리량이 붕괴하지 않도록 해야 한다.

### C3. 용량 초과 시 유효 처리량 보호 · 25

**평가 항목**
예매 오픈 시 주어진 처리 용량을 넘는 조회·점유 요청의 수락·대기·거절과 재시도 흐름을 평가하며, 자원 증설에 따른 확장이나 접수 완료 주문의 장애 복구는 별도로 다룬다.

| Level | 기준 |
|---|---|
| 0 | 조회·점유 요청이 처리 용량을 초과할 때 적체와 재시도로 유효 완료량이 붕괴할 수 있는 문제를 고려하지 않는다. |
| 1 | 과부하 문제를 인식하고 대기열이나 요청 제한을 제안하지만, 어떤 구성요소가 수락량을 제한하고 초과 요청과 재시도를 어떻게 처리하는지 충분히 설명하지 못한다. |
| 2 | 조회·점유 경로에서 용량을 보호할 지점과 역할을 정하고, 수락한 요청은 처리하며 초과 요청은 제한된 대기나 거절로 다루는 흐름을 설명한다. 제한된 요청의 재시도가 즉시 부하로 되돌아오지 않게 하며 접수 전 제한과 접수 후 책임을 구분한다. |
| 3 | 2점 설계에 더해, 대기 적체나 하위 의존성 병목·다단계 재시도가 유입 제어의 효과를 약화시키는 한계를 설명한다. 관련 지점의 제어를 보완하고, 용량 초과 부하 시험에서 수락 요청의 유효 완료량과 적체를 관찰하는 개선을 제시한다. |

## NFR-4. Scalability

**요구 수준**
`scalability` — 특정 공연에 요청이 집중되는 조건에서도 처리 자원과 작업 분담을 늘려 처리 가능한 범위를 확대할 수 있어야 한다. 동일 좌석의 배정 경합처럼 병렬화할 수 없는 한계는 구분하고, 공연 전체 조회와 개별 좌석 점유 각각의 확장 병목을 설명할 수 있어야 한다. 선형 확장이나 특정 분할 기술은 요구하지 않는다.
요청량이 증가할 때 자원과 처리 분담을 늘려 조회·점유 처리 범위를 확장할 수 있어야 하며, 특정 공연에 대한 집중 부하가 하나의 분할 단위에 고착되지 않도록 해야 한다.

### C4. 집중 공연의 처리 분담과 확장 · 20

**평가 항목**
특정 공연에 집중되는 전체 좌석 조회와 개별 좌석 점유를 자원 추가 및 작업 분담으로 확장하는 설계를 평가하며, 고정 용량에서 초과 요청을 제한하는 판단은 제외한다.

| Level | 기준 |
|---|---|
| 0 | 요청 증가와 특정 공연 집중 시 처리 범위를 늘려야 하는 문제를 고려하지 않고, 모든 작업을 고정된 단일 처리 경로에 맡긴다. |
| 1 | 확장 필요성을 인식하고 서버 추가나 데이터 분할을 제안하지만, 특정 공연의 작업이 추가 자원에 어떻게 분담되는지 또는 조회·점유 경로가 어떻게 연결되는지 충분히 설명하지 못한다. |
| 2 | 조회·점유를 담당하는 구성요소와 분담 단위를 제시하고, 같은 공연의 작업도 추가 자원으로 나뉘는 기본 흐름을 설명한다. 공연 전체 조회 결과를 구성하는 경로와 개별 좌석 점유의 처리 위치를 연결하여 자원 추가가 처리 범위 증가로 이어짐을 보인다. |
| 3 | 2점 설계에 더해, 분담 후에도 남는 부하 편중이나 전체 조회의 취합 부담을 설명하고 분담 조정·조회 경로 개선 등 대응을 제시한다. 동일 좌석의 권리 변경은 병렬화에 한계가 있음을 구분하고, 분산 효과와 취합 부담 사이의 선택을 설명한다. |
