# 공연 좌석 티켓 예매

**설계 범위**
공연별 좌석 잔여 현황 조회, 좌석 임시 점유와 만료, 주문 생성과 외부 결제 결과에 따른 예매 확정 또는 해제까지 설계한다. 결제 대행사 내부 구현·환불·재판매·공연 추천은 제외한다.

**평가 초점**
동일 좌석의 중복 예매 방지, 점유 만료·지연 결제 응답·재시도의 상태 일관성, 예매 오픈 시 조회·점유 요청 폭증 대응, 접수된 주문의 장애 후 복구와 중복 확정 방지

**대상 연차** Senior\
**배점** 100

## NFR-1. Consistency

**요구 수준**
`consistency` — 동시 점유·확정 요청 중 유효한 좌석 권리를 얻는 요청만 성공한다. 합의된 시간 기준과 만료 경계에 따라 확정 또는 만료의 승자를 결정하며, 이전 점유의 만료 작업이나 지연 결제 결과는 새 점유·확정을 변경하지 않는다. 잔여 현황 조회에 지연을 허용하더라도 점유·확정 성공은 권위 있는 현재 상태로 판정한다.
같은 공연의 동일 좌석에 유효한 점유나 확정 예매가 중복 성립하지 않아야 하며, 만료 처리와 지연 결제 결과가 경합하더라도 이미 바뀐 좌석 소유 상태를 과거 요청이 덮어쓰지 않아야 한다.

### C1. 좌석 권리의 유일성과 상태 전이 · 30

**평가 항목**
공연별 동일 좌석의 점유·만료·확정에서 권위 있는 상태를 기준으로 유효한 권리만 성립시키는 판단을 평가하며, 장애 후 주문 복구 절차는 제외한다.

| Level | 기준 |
|---|---|
| 0 | 동일 좌석의 중복 점유·확정이나 과거 요청이 현재 좌석 권리를 덮어쓰는 문제를 고려하지 않는다. |
| 1 | 좌석 상태를 관리하는 구성요소와 주문·결제 처리의 역할을 구분하고, 현재 권리를 확인하여 점유한 뒤 만료 시 해제하거나 유효한 결제 결과로 확정하는 흐름을 설명하지만 경합 처리 방식은 구체화하지 못한다. |
| 2 | 조회 지연을 허용하더라도 점유·확정 성공은 권위 있는 상태로 판단한다. 유효성 검사와 변경을 원자적으로 연결하고, 시간 기준·만료 경계와 점유 식별 검증 또는 동등한 방식으로 동시 요청의 승자를 정하며 과거 만료·결제 결과가 새 권리를 변경하지 못하게 한다. |
| 3 | 2점 설계를 전제로, 동일 좌석의 충돌 집중 등에서 정확성을 지키는 메커니즘이 왜 대기나 재시도 한계에 도달하는지 분석한다. 동등한 정확성을 보장하는 대안의 경합 완화 이점과 비용 또는 위험을 비교하고 선택 근거를 설명한다. |

## NFR-2. Fault Tolerance

**요구 수준**
`fault_tolerance` — 접수 완료한 주문은 장애 후 식별하여 처리를 재개할 수 있고, 결과가 불명확한 결제 시도는 외부 결과와 대사할 수 있다. 동일 요청과 결제 이벤트의 재처리는 추가 주문이나 중복 확정·해제를 만들지 않는다. 만료 후 도착한 결제 성공도 현재 좌석 권리를 침해하지 않으며, 미해결 상태를 추적할 수 있어야 한다.
접수한 주문과 결제 시도의 처리 상태를 장애 후 복구할 수 있어야 하며, 요청 재시도와 결제 결과의 중복·지연 전달에도 동일 주문의 확정 또는 해제가 중복 반영되지 않아야 한다.

### C2. 접수 주문의 장애 복구와 멱등 처리 · 25

**평가 항목**
접수 완료한 주문과 결제 시도의 보존·재개·대사 및 재처리의 중복 반영 방지를 평가하며, 좌석 경합의 승자 결정과 환불 절차는 제외한다.

| Level | 기준 |
|---|---|
| 0 | 접수한 주문의 처리 중단이나 결제 결과 불명확 상태를 장애 후 복구해야 한다는 문제를 고려하지 않는다. |
| 1 | 주문·결제 시도를 저장하고, 복구 담당이 미완료 건을 찾아 외부 결제 결과를 확인한 뒤 주문을 확정 또는 해제로 이어가는 흐름을 설명한다. 재처리 시 기존 결과를 확인하지만 중단 지점과 중복 실행에 대한 구체적 보장은 부족하다. |
| 2 | 접수 완료 전에 복구에 필요한 주문·결제 시도를 보존하고, 중단된 작업의 식별·재개와 불명확한 결제 결과의 대사 방식을 설명한다. 재시도·중복 이벤트의 식별과 결과 반영을 연결해 추가 주문이나 중복 확정·해제를 막고, 만료 후 결제 성공도 현재 권리를 보존하며 미해결 상태로 추적한다. |
| 3 | 2점 설계를 전제로, 외부 결과 확인 불가나 복구와 자동 재시도의 장기 중첩 등에서 선택한 복구 방식이 왜 한계에 이르는지 분석한다. 대사·재처리 대안의 복구 진전 이점과 외부 호출 비용 또는 중복 처리 위험을 비교하고 선택 근거를 설명한다. |

## NFR-3. High Throughput

**요구 수준**
`throughput` — 조회·점유 요청의 유입을 처리 용량 이상으로 높이는 부하 시험에서도, 수락한 요청의 유효 완료량이 과부하와 재시도 증폭 때문에 급격히 붕괴하지 않아야 한다. 초과 요청은 통제 가능한 대기나 거절 등으로 다루고, 접수 완료한 주문의 복구 책임과 접수 전 유입 제한을 구분한다.
예매 오픈 시 조회·점유 요청이 처리 용량을 초과하더라도 과부하와 재시도 증폭으로 유효 처리량이 붕괴하지 않도록 해야 한다.

### C3. 용량 초과 시 유효 처리량 유지 · 25

**평가 항목**
주어진 처리 용량에서 조회·점유 요청의 초과 유입과 재시도 증폭을 제어하는 판단을 평가하며, 접수 전 제한과 접수 후 복구 책임을 구분하고 자원 증설 효과는 제외한다.

| Level | 기준 |
|---|---|
| 0 | 예매 오픈의 초과 유입과 재시도 증폭이 수락한 요청의 유효 완료량을 붕괴시킬 수 있다는 문제를 고려하지 않는다. |
| 1 | 조회·점유 요청이 유입 제어를 거쳐 처리 구성요소와 저장소로 전달되는 흐름을 설명하고, 수락한 요청은 완료하며 초과 요청은 대기 또는 거절하도록 구분한다. 다만 제한의 동작 조건이나 재시도 증폭 대응은 구체화하지 못한다. |
| 2 | 처리 여력이나 적체에 따른 유입 제한 조건과 초과 요청의 대기·거절 처리를 설명한다. 재시도 증폭과 하위 의존성 병목을 억제하고 접수 주문의 복구 책임은 유지하며, 용량 초과 부하 시험에서 수락 요청의 유효 완료량이 급격히 붕괴하지 않는지 확인한다. |
| 3 | 2점 설계를 전제로, 병목 이동이나 제어 반응 지연 등에서 선택한 제한 방식이 왜 유효 처리량을 유지하지 못하는지 분석한다. 대기와 거절 등 대응 대안의 완료량 유지 이점과 적체·재시도 비용 또는 위험을 비교하고 선택 근거를 설명한다. |

## NFR-4. Scalability

**요구 수준**
`scalability` — 특정 공연에 요청이 집중되는 조건에서도 처리 자원과 작업 분담을 늘려 처리 가능한 범위를 확대할 수 있어야 한다. 동일 좌석의 배정 경합처럼 병렬화할 수 없는 한계는 구분하고, 공연 전체 조회와 개별 좌석 점유 각각의 확장 병목을 설명할 수 있어야 한다. 선형 확장이나 특정 분할 기술은 요구하지 않는다.
요청량이 증가할 때 자원과 처리 분담을 늘려 조회·점유 처리 범위를 확장할 수 있어야 하며, 특정 공연에 대한 집중 부하가 하나의 분할 단위에 고착되지 않도록 해야 한다.

### C4. 집중 공연의 처리 분담과 확장 한계 · 20

**평가 항목**
특정 공연에 조회·점유 요청이 집중될 때 자원 추가와 작업 분담이 실제 처리 범위 확대로 이어지는지를 평가하며, 고정 용량에서의 유입 제한은 제외한다.

| Level | 기준 |
|---|---|
| 0 | 자원을 늘려도 특정 공연의 작업이 하나의 처리 단위에 집중되어 확장이 막힐 수 있다는 문제를 고려하지 않는다. |
| 1 | 조회·점유 작업을 여러 처리 자원에 배분하고, 전체 좌석 조회 결과를 모으며 개별 좌석 점유를 담당 자원으로 전달하는 흐름을 설명한다. 다만 특정 공연에 집중된 요청이 단일 처리 단위에 고착되는 문제의 해결은 부족하다. |
| 2 | 특정 공연 내부의 작업도 추가 자원에 분담되는 기준과 요청 전달 방식을 설명한다. 전체 조회의 결과 집계와 개별 점유의 집중 병목에 대한 대응을 제시하고, 서로 다른 좌석의 병렬 처리 확대와 동일 좌석 배정 경합의 비병렬 한계를 구분한다. |
| 3 | 2점 설계를 전제로, 작업 편중이나 전체 조회의 집계량 증가가 어떤 조건에서 자원 추가 효과를 제한하는지 분석한다. 분담 단위나 조회 구성 대안의 병렬 처리 이점과 집계 비용 또는 운영 위험을 비교하고, 동일 좌석의 정확성 경계를 유지하는 선택 근거를 설명한다. |
