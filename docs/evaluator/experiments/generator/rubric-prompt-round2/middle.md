# 공연 좌석 티켓 예매

**설계 범위**
공연별 좌석 잔여 현황 조회, 좌석 임시 점유와 만료, 주문 생성과 외부 결제 결과에 따른 예매 확정 또는 해제까지 설계한다. 결제 대행사 내부 구현·환불·재판매·공연 추천은 제외한다.

**평가 초점**
동일 좌석의 중복 예매 방지, 점유 만료·지연 결제 응답·재시도의 상태 일관성, 예매 오픈 시 조회·점유 요청 폭증 대응, 접수된 주문의 장애 후 복구와 중복 확정 방지

**대상 연차** Middle\
**배점** 100

## NFR-1. Consistency

**요구 수준**
`consistency` — 동시 점유·확정 요청 중 유효한 좌석 권리를 얻는 요청만 성공한다. 합의된 시간 기준과 만료 경계에 따라 확정 또는 만료의 승자를 결정하며, 이전 점유의 만료 작업이나 지연 결제 결과는 새 점유·확정을 변경하지 않는다. 잔여 현황 조회에 지연을 허용하더라도 점유·확정 성공은 권위 있는 현재 상태로 판정한다.
같은 공연의 동일 좌석에 유효한 점유나 확정 예매가 중복 성립하지 않아야 하며, 만료 처리와 지연 결제 결과가 경합하더라도 이미 바뀐 좌석 소유 상태를 과거 요청이 덮어쓰지 않아야 한다.

### C1. 좌석 권리의 유일성과 상태 전이 · 30

**평가 항목**
같은 공연의 동일 좌석에 대한 점유·확정의 유일성과 만료·지연 결제 결과의 상태 전이를 평가하되, 조회 최신성이나 장애 후 주문 복구 절차는 평가하지 않는다.

| Level | 기준 |
|---|---|
| 0 | 동일 좌석에 중복 점유·확정이 성립하거나 과거 요청이 현재 좌석 권리를 변경할 수 있는 문제를 고려하지 않는다. |
| 1 | 중복 배정과 만료에 따른 상태 변경 문제를 인식하고 잠금이나 조건부 변경 등의 방향을 제시하지만, 유효성 판단과 점유·확정·해제 흐름의 연결이 불완전하다. |
| 2 | 좌석 상태를 관리하는 구성요소의 역할과 점유·만료·확정·해제의 기본 흐름을 설명한다. 시간 기준과 만료 경계를 정하고, 조회 결과와 별개로 현재 권리의 유효성 확인과 상태 변경을 원자적으로 처리한다. |
| 3 | 2점 설계에 더해, 이전 점유의 만료 작업이나 지연 결제 결과가 새 점유를 덮어쓰는 대표 상황을 설명하고, 점유 식별자 검증 등 현재 권리를 보호하는 개선 방안을 제시한다. |

## NFR-2. Fault Tolerance

**요구 수준**
`fault_tolerance` — 접수 완료한 주문은 장애 후 식별하여 처리를 재개할 수 있고, 결과가 불명확한 결제 시도는 외부 결과와 대사할 수 있다. 동일 요청과 결제 이벤트의 재처리는 추가 주문이나 중복 확정·해제를 만들지 않는다. 만료 후 도착한 결제 성공도 현재 좌석 권리를 침해하지 않으며, 미해결 상태를 추적할 수 있어야 한다.
접수한 주문과 결제 시도의 처리 상태를 장애 후 복구할 수 있어야 하며, 요청 재시도와 결제 결과의 중복·지연 전달에도 동일 주문의 확정 또는 해제가 중복 반영되지 않아야 한다.

### C2. 접수 주문의 복구와 중복 반영 방지 · 25

**평가 항목**
접수 완료한 주문과 결제 시도의 상태 보존·재개·대사 및 재처리 결과의 중복 반영 방지를 평가하며, 정상 처리 중 좌석 권리의 경합 제어와 금전 반환 절차는 제외한다.

| Level | 기준 |
|---|---|
| 0 | 접수 후 장애로 주문이나 결제 처리 상태를 잃는 문제와 재처리로 동일 결과가 중복 반영되는 문제를 고려하지 않는다. |
| 1 | 주문 상태 보존과 재시도 필요성을 인식하고 저장이나 멱등 처리 방향을 제시하지만, 미완료 주문 식별부터 결제 결과 확인과 처리 재개까지의 흐름이 불완전하다. |
| 2 | 주문·결제 시도 식별자와 처리 상태를 보존하고 미완료 작업을 찾아 재개하는 기본 흐름을 설명한다. 불명확한 결제 결과는 외부 상태와 대사하며, 이미 반영한 결과를 구분해 추가 주문이나 중복 확정·해제를 막는다. |
| 3 | 2점 설계에 더해, 결과 반영 도중 장애나 복구 작업과 결제 재전달의 중첩에서 생길 수 있는 누락을 설명하고, 재개 기준 보완이나 미해결 상태 추적 등 기본적인 개선 방안을 제시한다. |

## NFR-3. High Throughput

**요구 수준**
`throughput` — 조회·점유 요청의 유입을 처리 용량 이상으로 높이는 부하 시험에서도, 수락한 요청의 유효 완료량이 과부하와 재시도 증폭 때문에 급격히 붕괴하지 않아야 한다. 초과 요청은 통제 가능한 대기나 거절 등으로 다루고, 접수 완료한 주문의 복구 책임과 접수 전 유입 제한을 구분한다.
예매 오픈 시 조회·점유 요청이 처리 용량을 초과하더라도 과부하와 재시도 증폭으로 유효 처리량이 붕괴하지 않도록 해야 한다.

### C3. 용량 초과 시 유효 처리량 유지 · 25

**평가 항목**
예매 오픈 시 조회·점유 요청이 현재 처리 용량을 초과하는 상황의 유입 제어와 재시도 증폭 방지를 평가하되, 자원 증설에 따른 확장 효과나 접수 주문의 복구 구현은 평가하지 않는다.

| Level | 기준 |
|---|---|
| 0 | 조회·점유 요청의 과부하와 재시도 증폭으로 수락한 요청의 유효 완료량이 무너지는 문제를 고려하지 않는다. |
| 1 | 처리 용량을 넘는 요청의 제한 필요성을 인식하고 대기나 거절 방향을 제시하지만, 제한 지점과 수락한 요청의 처리 흐름 또는 재시도 안내가 불완전하다. |
| 2 | 유입 제어 구성요소가 용량에 맞춰 요청을 수락하고 초과분을 통제된 대기나 거절로 처리하는 흐름을 설명한다. 재시도가 부하를 증폭하지 않게 다루며, 접수 전 제한과 접수 완료 주문의 처리 책임을 구분한다. |
| 3 | 2점 설계에 더해, 대기 적체나 하위 저장소 포화 등 대표적인 처리량 저하 원인을 설명하고 제어 지점이나 유입 정책을 보완한다. 용량 초과 부하에서 수락 요청의 유효 완료량을 관찰하는 방법도 제시한다. |

## NFR-4. Scalability

**요구 수준**
`scalability` — 특정 공연에 요청이 집중되는 조건에서도 처리 자원과 작업 분담을 늘려 처리 가능한 범위를 확대할 수 있어야 한다. 동일 좌석의 배정 경합처럼 병렬화할 수 없는 한계는 구분하고, 공연 전체 조회와 개별 좌석 점유 각각의 확장 병목을 설명할 수 있어야 한다. 선형 확장이나 특정 분할 기술은 요구하지 않는다.
요청량이 증가할 때 자원과 처리 분담을 늘려 조회·점유 처리 범위를 확장할 수 있어야 하며, 특정 공연에 대한 집중 부하가 하나의 분할 단위에 고착되지 않도록 해야 한다.

### C4. 집중 부하의 처리 분담과 확장 · 20

**평가 항목**
특정 공연에 조회·점유 요청이 집중될 때 자원과 작업 분담을 늘리는 설계 및 조회 집계·좌석 경합의 확장 한계를 평가하며, 고정 용량에서 초과 요청을 제한하는 정책은 평가하지 않는다.

| Level | 기준 |
|---|---|
| 0 | 특정 공연의 요청이 하나의 처리 단위에 집중되어 자원을 추가해도 처리 범위가 늘지 않는 문제를 고려하지 않는다. |
| 1 | 집중 부하를 분산할 필요성을 인식하고 서버 추가나 작업 분할을 제안하지만, 동일 공연의 조회·점유 작업이 추가 자원에 배분되는 흐름을 충분히 설명하지 못한다. |
| 2 | 동일 공연 안에서도 작업을 나눌 수 있는 처리 단위와 구성요소의 역할을 설명한다. 자원 추가 시 개별 좌석 점유가 분담되고 공연 전체 잔여 현황이 조회·집계되는 기본 흐름을 제시한다. |
| 3 | 2점 설계에 더해, 전체 조회의 집계 부담과 동일 좌석 변경의 직렬화 한계를 구분한다. 좌석 정확성을 위해 경합 구간의 병렬성이 제한됨을 설명하고, 다른 좌석의 분담 확대나 조회 경로 보완 등 개선 방안을 제시한다. |
