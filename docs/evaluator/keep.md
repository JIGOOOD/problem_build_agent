# Keep 문장 선택 품질 평가 기준

## 평가 목적

Keep이 NFR 도출에 필요한 문장을 올바르게 선택하고, 원문의 의미와 보관 예산을 지켰는지 평가한다.

평가에는 설계 범위·평가 초점, 당시 fetch 원문(문장 번호 포함), 실제 보관 문장, 문서별 `keep_budget_chars`를 사용한다. fetch 이후의 원문은 추측하거나 다시 수집하지 않는다.

판정은 `Pass` / `Fail`이다. 판단에 필요한 자료가 없으면 `null`(판단 불가)로 기록하고 점수를 만들지 않는다. 파일 누락·모델 호출 실패·응답 오류는 별도의 평가 오류다.

---

## 1. 보관 문장별 평가

평가 단위: 실제 보관한 문장 각각

### 1-1. NFR 근거 선택 적절성

- Pass: 문장이 평가 초점과 관련된 **NFR의 필요성, 품질 조건, 설계 방법 또는 그 한계** 중 하나를 뒷받침한다.
- Fail: 문장이 제품 소개·홍보·범위 밖 정보 등으로, 평가 초점에 해당하는 NFR 도출이나 설계 판단에 근거를 제공하지 않는다.

선택한 문장의 ID와 뒷받침하는 NFR 또는 설계 판단을 기록한다. 보관 문장이 없으면 이 항목은 평가하지 않는다.

### 1-2. 원문 의미 및 문맥 보존

- Pass: 보관 문장이 원문의 의미를 유지하고, 의미에 영향을 주는 주체·조건·수치·부정·예외·한계를 빠뜨리지 않는다. 공백·줄바꿈만 바뀐 경우는 허용한다.
- Fail: 문장을 변경하거나 필요한 문맥을 누락하여 원문의 의미, 적용 조건 또는 보장 범위가 달라진다.

원문 문장 번호와 달라진 부분을 기록한다. 원문을 확인할 수 없으면 `null`이다. 보관 문장이 없으면 이 항목은 평가하지 않는다.

## 2. 원문 문서별 평가

평가 단위: fetch된 원문 문서 각각 (전체를 버린 문서 포함)

### 2-1. 중요한 NFR 근거 누락

- Pass: 해당 문서에서 **보관할 수 있었는데 빠뜨린 중요한 근거**가 확인되지 않는다.
- Fail: 아래 조건을 **모두 충족하는 문장**을 누락했다.
  1. 해당 문장이 평가 초점의 핵심 NFR 선정·요구 수준·설계 판단에 영향을 준다.
  2. 같은 의미의 근거가 다른 보관 문장이나 다른 보관 문서에도 없다.
  3. 당시 문서별 보관 예산 안에서 덜 중요한 문장을 대체하거나 남은 예산으로 보관할 수 있었다.

Fail이면 누락 문장 번호, 왜 중요한지, 교체 가능한 보관 문장(또는 남은 예산)을 기록한다. 단순히 관련 문장이 더 있다는 이유만으로 Fail하지 않는다. 원문이나 예산 가능성을 확인할 수 없으면 `null`이다.

### 2-2. 문서별 보관 예산 준수

- Pass: 해당 문서의 보관 글자 수가 `keep_budget_chars` 이하이다.
- Fail: 해당 문서의 보관 글자 수가 `keep_budget_chars`를 초과한다.

글자 수와 예산 값을 기록한다. 예산 값이 없으면 `null`이다. 글자 수는 **코드로 계산**하고 LLM에게 추정시키지 않는다.

---

## 3. 평가 결과 기록 형식

- 평가 대상: 문서 ID 또는 문서 ID + 보관 문장 ID
- 평가 기준: `1-1`, `1-2`, `2-1`, `2-2`
- 판정: `Pass` / `Fail` / `null`
- 적용 기준: 실제로 적용한 Pass/Fail 조건
- 판단 근거: 원문 문장 번호·보관 여부·판정 이유 (`null`이면 부족한 정보)

Pass는 1, Fail은 0으로 기록한다. 통과율은 `Pass / (Pass + Fail) × 100`이며 `null`은 분모에서 제외한다. 문장별·문서별 통과율은 **별도로 집계**한다.
