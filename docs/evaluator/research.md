# Research 단계 품질 평가 기준

## 평가 목적

Agent가 설계 주제와 평가 초점을 분석해 NFR 후보를 도출하고, 검색 쿼리 작성 → Search → 출처 선별 → Fetch를 거쳐 후보를 판단할 근거를 확보했는지 평가한다.

평가에는 해당 실행에 저장된 brief, 후보군, 쿼리, 검색 결과, 출처 선정 결과, Fetch 본문 및 Research 결과만 사용한다. 웹을 다시 검색하지 않으며, NFR 후보를 최종 선정된 정답으로 취급하지 않는다. Keep 단계의 문장 선택과 누락은 평가하지 않는다.

각 기준은 Pass / Fail로 판정한다. 필요한 실행 기록이 없어 확인할 수 없으면 `null`과 사유를 남긴다. 기록상 수행해야 할 작업을 하지 않은 것이 확인된다면 `Fail`이다. API 호출 장애 등 실행 오류는 품질 판단과 구분해 기록한다.

---

## 1. NFR 후보군 평가

평가 단위: 후보군 전체 또는 각 NFR 후보

### 1-1. 평가 초점 반영

- Pass: brief에 명시된 핵심 평가 초점마다 이를 검증할 수 있는 NFR 후보가 있다. 후보의 명칭이나 개수는 고정하지 않는다.
- Fail: 명시된 핵심 평가 초점에 대응하는 후보가 빠져 있어 해당 설계 문제를 조사할 계획 자체가 없다.

### 1-2. 후보 도출의 타당성

- Pass: 후보가 설계 범위 내의 구체적인 시스템 동작이나 위험과 연결되며, 왜 해당 품질 속성을 검증할 필요가 있는지 설명한다.
- Fail: 후보 이름만 제시하거나 설계 범위·평가 초점과 연결되지 않는 NFR을 근거 없이 후보에 넣는다.

검증 전 후보를 가설로 남기는 것은 허용한다. 검색 근거가 아직 없다는 이유만으로 Fail하지 않는다.

---

## 2. 검색 쿼리 평가

평가 단위: 각 NFR 후보에 연결된 검색 쿼리 묶음

### 2-1. 후보 검증에 적합한 쿼리

- Pass: 후보에 대해 실제 서비스 기능·시스템 동작과 검증하려는 품질 문제를 연결한 검색 쿼리가 있고, 관련 설계 방법이나 제약·한계를 확인할 자료를 찾을 수 있도록 구성했다.
- Fail: 후보에 대한 검색 쿼리가 없거나, NFR 이름만 반복하는 일반 검색·무관한 검색에 그쳐 후보의 타당성을 판단할 근거를 찾기 어렵다.

모든 쿼리에 기술 이름이 포함될 필요는 없다. 하나의 쿼리가 여러 후보를 검증해도 된다.

---

## 3. Search 결과 평가

평가 단위: 실행된 검색 쿼리 각각

### 3-1. 검색 결과의 관련성

- Pass: 반환된 결과에 검색 쿼리의 설계 문제와 연결되는 문서 후보가 있어 후속 본문 확인 대상으로 검토할 수 있다.
- Fail: 결과가 일반 소개·광고·다른 주제에 치우쳐 후보 검증에 사용할 문서 후보가 없는데도 검색을 충분한 근거 탐색으로 취급한다.

검색 서비스 오류는 별도로 기록한다. 검색 결과에 나온 제목·요약만으로 기술적 주장이 사실이라고 판정하지 않는다.

---

## 4. Fetch 대상 선별 평가

평가 단위: 본문 수집 대상으로 선택한 문서 각각

### 4-1. 출처 선정의 타당성

- Pass: 검색 결과 중 설계 범위와 후보 검증에 관련되고 게시 주체를 식별할 수 있는 문서를 선택한다. 동일 내용의 중복 URL이나 근거가 부족한 목록·홍보 페이지를 불필요하게 우선하지 않는다.
- Fail: 관련성이나 출처를 확인하지 않은 채 무관한·중복된·본문 근거가 없는 문서를 선택하고, 검색 결과에 있던 더 적절한 출처를 뚜렷한 이유 없이 제외한다.

공식 출처가 아니라는 이유만으로 Fail하지 않는다. 이 평가는 저장된 검색 결과에서 실제 선택 가능한 문서를 기준으로 한다.

---

## 5. Fetch 결과 평가

평가 단위: Fetch를 시도한 문서 각각

### 5-1. 본문 수집의 유효성

- Pass: 선택한 문서의 실제 본문을 정상적으로 수집하여 후속 근거 확인에 사용할 수 있다.
- Fail: 본문 대신 검색 요약이나 다른 문서 내용을 수집하고 정상적인 본문으로 처리한다.

판단 불가/실행 오류: 접근 차단·타임아웃 등으로 본문 수집에 실패한 경우는 별도로 기록한다.

---

## 6. Research 전체 평가

평가 단위: Research 단계의 최종 수집 결과 전체

### 6-1. 핵심 평가 초점의 근거 확보

- Pass: brief의 핵심 평가 초점마다 후보의 타당성을 판단하는 데 쓸 실제 본문 근거가 확보되어 있다. 근거가 없는 후보를 무리하게 확정하지 않는다.
- Fail: 중요한 평가 초점에 대한 본문 근거가 빠졌거나, 제목·검색 요약만을 근거로 충분히 조사했다고 판단한다.

### 6-2. Research 판단과 수집 근거의 일치

- Pass: Research 결과의 후보 설명이나 기술적 주장이 수집된 본문으로 뒷받침되며, 원문의 적용 조건·수치·한계를 임의로 확정하거나 확대하지 않는다.
- Fail: 본문에 없는 보장·수치·조건을 만들어 내거나, 다른 맥락의 주장을 일반화하여 후보의 근거로 사용한다.

---

## 7. 평가 결과 기록 형식

각 판정에는 다음 정보를 기록한다.

- 평가 대상: Research 전체, NFR 후보 ID, 검색 쿼리 ID 또는 문서 ID·URL
- 평가 항목: 위 숫자 ID와 이름 (예: `2-1. 후보 검증에 적합한 쿼리`)
- 판정: `Pass` / `Fail` / `null` (판단 불가)
- 적용 기준: 판정에 사용한 Pass 또는 Fail 조건
- 판단 근거: brief의 평가 초점과 실제 후보·쿼리·검색 결과·문서 내용을 연결한 구체적인 이유
- 확인 위치: 가능하면 후보 ID, 쿼리, 문서 ID·URL, 원문 위치를 명시

판단 근거 없이 Pass / Fail만 반환하지 않는다. `null`일 때는 부족한 기록을 명시하고 점수를 생성하지 않는다. Pass=1, Fail=0으로 저장하며, 판단 불가와 실행 오류는 통과율에서 제외한다.
