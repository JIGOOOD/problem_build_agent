# YouTube 동영상 업로드 및 스트리밍

**설계 범위**
대용량 동영상 업로드, 원본 저장과 형식 변환·세그먼트 생성, 중단된 업로드 재개, 영상 스트리밍 및 대규모 시청 요청 분산까지 설계한다. 검색·추천·댓글·구독은 제외한다.

**평가 초점**
업로드 중단 후 재개, 저대역폭 환경의 끊김 없는 재생, 대량 영상 변환 작업 처리, 대규모 시청 트래픽 분산

**대상 연차** Middle\
**배점** 100

## NFR-1. Low Latency

**요구 수준**
`latency` — 시스템은 느리거나 변동이 큰 네트워크에서도 재생 시작을 지연시키지 않고, 전송 가능한 화질을 조정해 버퍼링을 줄여야 한다.

### C1. 세그먼트 기반 적응형 스트리밍 · 35

**평가 항목**
전체 영상 다운로드 없이 재생을 시작하고, 네트워크 상태 변화에 따라 재생 중 끊김을 줄이는 흐름을 평가한다.

| Level | 기준 |
| --- | --- |
| 0 | 영상 전체를 내려받아야 재생할 때 발생하는 시작 지연과 버퍼링을 고려하지 않는다. |
| 1 | 영상을 짧은 세그먼트로 나누어 전체 다운로드 전에 재생하는 방안을 제시하지만, 저장소와 플레이어의 역할이나 세그먼트를 받는 순서는 충분히 설명하지 못한다. |
| 2 | 영상을 짧은 세그먼트로 나누어 저장하고, 클라이언트가 재생 순서대로 필요한 부분만 받아 바로 재생하는 흐름을 설명한다. 여러 화질을 준비하고 네트워크 상태에 맞는 화질의 세그먼트를 선택해 버퍼링을 줄인다. |
| 3 | 2점에 더해, 순간적인 네트워크 변화마다 화질을 바꾸면 전환이 잦아질 수 있음을 설명한다. 최근 전송 상태를 함께 보거나 최소 유지 시간을 두는 등 화질 변경을 안정화하는 개선을 제시한다. |

## NFR-2. High Throughput

**요구 수준**
`throughput` — 시스템은 대량으로 업로드되는 동영상을 여러 재생 형식으로 변환하되, 긴 인코딩 작업으로 변환 대기열이 계속 누적되지 않도록 처리해야 한다.

### C2. 대규모 동영상 변환 작업 처리 · 25

**평가 항목**
원본 업로드와 영상 변환을 분리하고 여러 화질·형식의 동영상을 처리하는 기본 흐름을 평가한다.

| Level | 기준 |
| --- | --- |
| 0 | 업로드된 영상을 여러 재생 형식으로 변환할 때 발생하는 처리 부하를 고려하지 않는다. |
| 1 | 원본을 여러 화질·형식으로 변환하는 작업을 업로드 요청과 분리하는 방안을 제시하지만, 원본 저장소와 변환 서비스의 역할이나 결과를 보관하는 흐름은 충분히 설명하지 못한다. |
| 2 | 원본 영상을 저장한 뒤 별도 처리 서비스가 여러 화질·형식으로 변환해 보관하는 흐름을 설명한다. 업로드 요청과 변환 작업을 분리한다. |
| 3 | 2점에 더해, 긴 영상을 통째로 변환하면 작업이 오래 걸려 적체될 수 있음을 설명한다. 영상을 세그먼트로 나누어 여러 작업자가 병렬 처리하도록 개선한다. |

---

## NFR-3. High Availability

**요구 수준**
`availability` — 시스템은 대용량 동영상 업로드가 네트워크 문제로 중단되어도 이미 업로드한 부분을 유지하고 나머지 부분부터 재개할 수 있어야 한다.

### C3. 대용량 업로드 중단 후 재개 · 20

**평가 항목**
대용량 파일 업로드가 중단되어도 완료된 부분을 재사용하며 이어서 전송하는 기본 흐름을 평가한다.

| Level | 기준 |
| --- | --- |
| 0 | 대용량 동영상 업로드가 도중에 끊길 수 있다는 문제를 고려하지 않는다. |
| 1 | 파일을 나누어 보내고 완료된 부분을 보관해 중단 후 남은 부분을 전송하는 방안을 제시하지만, 부분별 완료 기록과 재전송 흐름은 충분히 설명하지 못한다. |
| 2 | 동영상을 여러 부분으로 나누어 저장소에 업로드하고 각 부분의 완료 여부를 기록하는 흐름을 설명한다. 중단되면 남은 부분부터 다시 전송한다. |
| 3 | 2점에 더해, 재시작 시 클라이언트의 완료 기록이 실제 저장 상태와 다를 수 있음을 설명한다. 저장소에서 완료된 부분을 확인해 누락된 부분만 전송한다. |

---

## NFR-4. High Scalability

**요구 수준**
`scalability` — 시스템은 대규모 시청자가 동일한 영상을 동시에 요청하더라도 원본 저장소에 읽기 부하가 집중되지 않도록 콘텐츠 전달 경로를 확장해야 한다.

### C4. 대규모 영상 시청 요청 분산 · 20

**평가 항목**
많은 시청자의 영상 세그먼트 요청을 원본 저장소에 집중시키지 않고 분산하는 기본 전달 흐름을 평가한다.

| Level | 기준 |
| --- | --- |
| 0 | 많은 사용자가 동시에 영상을 시청할 때 원본 저장소에 조회가 집중되는 문제를 고려하지 않는다. |
| 1 | 영상 세그먼트를 캐시 서버에서 제공해 원본 조회를 줄이는 방안을 제시하지만, 캐시 서버와 원본 저장소의 역할이나 캐시에 없는 세그먼트의 조회 흐름은 충분히 설명하지 못한다. |
| 2 | CDN을 두어 영상 세그먼트를 사용자와 가까운 캐시 서버에서 제공하고, 없는 세그먼트만 원본 저장소에서 가져오는 기본 흐름을 설명한다. |
| 3 | 2점에 더해, 캐시에 없는 세그먼트 요청이 많으면 원본 부하가 여전히 커질 수 있음을 설명한다. 자주 시청하는 영상의 세그먼트를 캐시에 유지해 원본 조회를 줄인다. |
