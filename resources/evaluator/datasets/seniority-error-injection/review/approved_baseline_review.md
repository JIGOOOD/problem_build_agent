# 정상 데이터 한 쌍 — 연차 대응 검토

## 파일과 사용 범위

- `01_clean/middle.md`: 최초 `seniority_eval_dataset.zip`의 Middle을 바이트 단위로 그대로 복사했다.
- `01_clean/senior.md`: Middle의 설계 범위·평가 초점·NFR 요구 수준·Criterion·배점은 유지하고 Senior의 Level 서술을 다시 작성했다.
- 대상은 `3-5. 대상 연차 적합성`과 `4-1. 연차별 실질적 차이`의 정상 대조군 한 쌍이다. 의도적으로 주입한 오류는 없다.
- 실제 평가기에는 두 루브릭과 사용자의 평가·연차 기준만 전달한다. 이 검토표는 정답 유출을 피하기 위해 전달하지 않는다.

## 적용한 연차 관계

대화에서 최종 수정한 기준을 사용했다. Middle 2점과 Senior 1점은 정상 흐름의 기본 설계, Middle 3점과 Senior 2점은 그 설계의 대표 문제 대응이라는 유사한 수준으로 맞췄다. Senior 2점에서는 처리 조건과 동작 원리를 추가로 명시하고, Senior 3점에서는 보장 경계와 선택의 비용을 분석하도록 했다.

같은 개선 방법이 Middle 3점과 Senior 2점에 등장하는 것 자체는 오류가 아니다. 추가로 설명해야 하는 필수 동작이 기술 이름이나 문장 길이 차이로 끝나는지를 확인한다. Senior 2점에 별도의 두 번째 한계 분석을 요구하지 않는다.

## 기준별 대응

| 항목 | Middle 2 ≈ Senior 1 | Middle 3의 개선 | Senior 2의 추가 필수 동작 | Senior 3의 분석·판단 |
|---|---|---|---|---|
| C1 · 좌석 점유와 예매 확정 | 좌석 상태를 보관하는 곳에서 한 요청만 점유하게 하고, 점유자를 확인하여 결제 결과에 따라 확정·해제한다. | 늦은 결제 응답이 만료된 점유를 확정하지 않도록 유효성을 다시 확인한다. | 점유 ID·현재 상태·만료 조건의 검사와 갱신을 원자적으로 묶는다. 확정과 해제의 조건을 구분하여 이전 점유의 응답이 새 점유를 변경하지 못하게 한다. | 만료·재점유·결제 응답의 순서별 결과, 잠금 대기와 조건부 갱신 재시도 비용, 외부 결제 대기와 좌석 변경의 처리 경계를 분석한다. |
| C2 · 접수 주문 보존과 재개 | 주문을 지속 저장한 뒤 접수 성공을 반환한다. 작업자는 미완료 주문을 처리하고 완료를 기록한다. | 완료 기록 전 장애로 같은 주문을 다시 처리할 수 있으므로 기존 처리 결과를 확인한다. | 주문별 확정 기록의 유일성과 확정 결과·완료 표시의 같은 트랜잭션 반영을 요구한다. 동시 재처리도 한 건만 커밋되고 기존 결과를 재사용한다. | 내부 트랜잭션에 포함되지 않는 외부 결제의 성공 여부를 대조하는 복구 경로와 대사 주기의 복구 지연·조회 부하를 분석한다. |
| C3 · 초과 유입과 적체 제어 | 앞단에서 처리 가능한 요청만 서비스로 보내고, 초과 요청은 대기 또는 거절한다. | 대기자가 같은 시점에 재시도하여 부하가 다시 몰리는 문제를 줄인다. | 여러 진입 서버가 하나의 처리 상한을 공유하고, 입장 조건 확인·처리 수 증가를 원자적으로 수행한다. 완료 시 중복 차감을 막으며 재시도에도 동일한 제한을 적용한다. | 공유 카운터 자체의 병목에 대해 중앙 집계와 서버별 상한 분할을 비교하고, 남는 용량 활용·조정 비용·장애 시 회수의 상충을 분석한다. |
| C4 · 인기 공연의 조회·점유 확장 | 조회와 점유 서버의 역할을 구분하고 공연별 요청을 여러 서버에 분산한다. | 한 공연으로 집중되는 요청을 좌석군 같은 더 작은 단위로 나눈다. | 요청만 아니라 실제 점유 상태도 여러 저장소에 분할한다. 분할표를 통해 해당 상태가 있는 곳으로 요청을 라우팅하고 조회 경로를 분리하여 단일 쓰기 저장소 병목을 줄인다. | 상태 이전과 라우팅 전환 중 두 쓰기 담당이 생기는 위험을 분석하고, 쓰기 중지 후 이전과 변경분 복제 후 전환의 중단 시간·동기화 비용을 비교한다. |

## Level 원문 대조

### C1. 좌석 점유와 예매 확정

| Level | Middle 원문 | Senior 원문 |
|---|---|---|
| 0 | 같은 좌석을 여러 사용자가 동시에 점유해 중복 예매될 수 있다는 문제를 고려하지 않는다. | 같은 좌석을 여러 사용자가 동시에 점유해 중복 예매될 수 있다는 문제를 고려하지 않는다. |
| 1 | 좌석 잠금이나 상태 확인을 제안하지만, 경쟁 요청 중 누가 점유하는지와 결제 후 확정하는 흐름을 설명하지 못한다. | 좌석 저장소에서 한 요청만 점유하게 하고, 점유자를 확인해 결제 결과에 따라 확정하거나 해제하는 흐름을 제시한다. 다만 확인 이후 만료·재점유가 끼어들 때 변경을 막는 구체적인 조건은 설명하지 못한다. |
| 2 | 좌석 상태를 관리하는 저장소에서 한 요청만 점유에 성공하게 하고, 점유자 확인 후 결제 결과에 따라 확정하거나 해제하는 기본 흐름을 설명한다. | 가용 좌석에 점유 ID·만료 시각을 원자적으로 기록한다. 확정은 점유 ID 일치·대기 상태·미만료 조건에서, 해제는 같은 ID·대기 상태에서 만료나 결제 실패 조건으로 원자 갱신해 오래된 응답이 새 점유나 확정을 바꾸지 못하게 한다. |
| 3 | 2점에 더해, 늦은 결제 응답이 만료된 점유를 확정할 수 있다는 한계를 설명한다. 확정 전에 점유 유효성을 다시 확인하는 기본 개선 방안을 제시한다. | 2점에 더해, 만료 해제·재점유·이전 결제 응답의 순서가 달라도 새 점유가 유지되는 근거를 분석한다. 좌석별 잠금과 조건부 갱신을 비교해 잠금 대기·충돌 재시도 비용을 설명하고, 외부 결제 대기와 좌석 변경의 처리 경계를 정당화한다. |

**기본 설명과 Senior 2점의 경계:** “결제 응답을 받으면 점유가 유효한지 확인한다”만으로는 Senior 2점이 아니다. 확인 직후 만료·재점유가 들어오는 상황을 막는 검사·갱신 결합 조건이 더 필요하다.

### C2. 접수 주문 보존과 재개

| Level | Middle 원문 | Senior 원문 |
|---|---|---|
| 0 | 접수한 주문이 처리 중 장애로 유실될 수 있다는 문제를 고려하지 않는다. | 접수한 주문이 처리 중 장애로 유실될 수 있다는 문제를 고려하지 않는다. |
| 1 | 장애 후 재시도하겠다고 제안하지만, 어떤 주문을 어디에 저장하고 누가 다시 처리하는지 설명하지 못한다. | 주문과 진행 상태를 저장한 뒤 접수 성공을 반환하고, 작업자가 미완료 주문을 찾아 처리한 뒤 완료로 기록하는 흐름을 제시한다. 다만 같은 주문이 다시 처리될 때 중복 확정을 막는 구체적인 조건은 설명하지 못한다. |
| 2 | 주문을 지속 저장한 뒤 접수 성공을 반환하고, 작업자가 미완료 주문을 찾아 처리한 후 완료 상태를 기록하는 기본 흐름을 설명한다. | 주문 접수·재개 흐름에서 주문 ID별 확정 기록에 유일성 제약을 두고, 확정 결과와 완료 상태를 같은 트랜잭션으로 저장한다. 재처리·중복 결제 통지는 기존 기록이 있으면 결과를 재사용하고, 없으면 새로 반영하되 경합한 작업 중 한 건만 커밋되게 한다. |
| 3 | 2점에 더해, 완료 기록 전에 장애가 나면 주문이 다시 처리될 수 있다는 한계를 설명한다. 기존 처리 결과를 확인해 중복 확정을 피하는 개선 방안을 제시한다. | 2점에 더해, 결제 성공 후 내부 기록 전에 장애가 난 상황에서 기존 결제 식별자로 외부 결과를 대조해 복구하는 흐름을 분석한다. 외부 결제까지 로컬 트랜잭션으로 묶을 수 없는 한계를 짚고, 대사 주기에 따른 복구 지연·조회 부하와 선택 근거를 설명한다. |

**기본 설명과 Senior 2점의 경계:** “이미 처리한 주문인지 확인한 뒤 처리한다”만으로는 Senior 2점이 아니다. 두 작업자가 동시에 미완료로 읽거나 효과 반영 직후 장애가 발생해도 중복 확정되지 않는 기록·반영 경계가 더 필요하다.

### C3. 초과 유입과 적체 제어

| Level | Middle 원문 | Senior 원문 |
|---|---|---|
| 0 | 예매 오픈 때 처리 능력을 넘는 요청으로 내부 작업이 무제한 쌓일 수 있다는 문제를 고려하지 않는다. | 예매 오픈 때 처리 능력을 넘는 요청으로 내부 작업이 무제한 쌓일 수 있다는 문제를 고려하지 않는다. |
| 1 | 요청을 대기시키거나 제한하겠다고 하지만, 제한 지점과 초과 요청의 처리 흐름을 설명하지 못한다. | 앞단에서 처리 가능한 수만 점유·주문 서비스로 보내고 초과 요청은 대기시키거나 거절하는 흐름을 제시한다. 다만 여러 진입 서버가 허용량을 나눠 쓰거나 대기자가 동시에 재시도할 때의 제어 방식은 설명하지 못한다. |
| 2 | 진입 요청을 앞단에서 제한해 처리 가능한 수만 점유·주문 서비스로 보내고, 나머지는 대기시키거나 거절하는 기본 흐름을 설명한다. | 진입 서버들이 처리 중 요청 수와 상한을 공유하고, 상한 미만일 때만 원자적으로 수를 늘려 요청을 전달한다. 완료는 요청 ID로 한 번만 차감한다. 거절된 클라이언트는 대기 간격에 임의 지연을 더하며, 재시도도 같은 진입 검사를 거치게 한다. |
| 3 | 2점에 더해, 대기 중인 사용자의 재시도가 동시에 몰려 다시 과부하가 생기는 한계를 설명한다. 재시도 시점을 분산하는 기본 개선 방안을 제시한다. | 2점에 더해, 모든 진입 서버가 공유 카운터를 갱신해 진입 판단 자체가 병목이 되는 상황을 분석한다. 전체 상한을 서버별로 나눠 관리하는 대안과 비교해 조정 비용·남는 용량의 활용·서버 장애 시 용량 회수의 상충을 설명하고 선택을 정당화한다. |

**기본 설명과 Senior 2점의 경계:** “임의 지연을 넣어 재시도를 분산한다”만으로는 Senior 2점이 아니다. 여러 진입 서버와 재시도가 함께 몰려도 공통 상한을 넘지 않는 입장 조건과 처리 수 관리가 더 필요하다.

### C4. 인기 공연의 조회·점유 확장

| Level | Middle 원문 | Senior 원문 |
|---|---|---|
| 0 | 인기 공연에 조회·점유가 몰릴 때 서버 확장이 필요하다는 문제를 고려하지 않는다. | 인기 공연에 조회·점유가 몰릴 때 서버 확장이 필요하다는 문제를 고려하지 않는다. |
| 1 | 서버를 늘리겠다고 제안하지만, 조회·점유 요청을 여러 서버에 어떻게 분산하는지 설명하지 못한다. | 조회 서버와 점유 서버의 역할을 나누고, 공연별 요청을 여러 처리 서버로 분산해 부하를 나누는 흐름을 제시한다. 다만 인기 공연 하나에 요청이 집중될 때 요청과 점유 데이터를 함께 나눌 방법은 설명하지 못한다. |
| 2 | 조회 서버와 점유 서버의 역할을 구분하고, 공연별 요청을 여러 처리 서버로 나눠 부하를 분담하는 기본 흐름을 설명한다. | 조회는 읽기 복제본이나 캐시로 보내고, 점유 상태는 공연 ID·좌석군 기준으로 여러 저장소에 분할한다. 라우터는 분할표로 담당 저장소를 찾아 같은 좌석의 변경을 같은 곳으로 보낸다. 서버만 늘려도 남는 단일 쓰기 저장소 병목을 줄이는 흐름을 설명한다. |
| 3 | 2점에 더해, 인기 공연 하나에 요청이 집중되면 공연별 분산만으로 병목이 남는 한계를 설명한다. 좌석군처럼 더 작은 단위로 점유 요청을 분산하는 개선 방안을 제시한다. | 2점에 더해, 좌석군 재배치 중 이전·새 저장소가 동시에 점유를 받는 위험을 분석한다. 쓰기를 멈춰 복사한 뒤 라우팅을 전환하는 방식과, 변경분을 복제한 뒤 쓰기 담당을 전환하는 방식을 비교해 중단 시간·상태 동기화 비용과 선택 근거를 설명한다. |

**기본 설명과 Senior 2점의 경계:** “좌석군별로 서버를 나눈다”만으로는 Senior 2점이 아니다. 점유 데이터의 저장 위치와 요청 전달 기준까지 설명해야 하며, 모든 요청이 다시 하나의 쓰기 저장소로 모이는 구조만으로는 충족하지 않는다.

| 항목 | 고유한 판단 대상 | 다른 항목의 설명으로 대체하지 않는 부분 |
|---|---|---|
| C1 | 서로 다른 요청이 같은 좌석의 소유권을 변경하는 조건 | 주문 재처리 기록만으로 점유·만료 경합 제어를 충족 처리하지 않는다. |
| C2 | 같은 주문·결제 결과가 다시 처리될 때의 효과와 복구 | 좌석 잠금만으로 주문 확정 효과와 완료 기록의 중복 방지를 충족 처리하지 않는다. 외부 결제 자체를 로컬 트랜잭션이 보장한다고 해석하지 않는다. |
| C3 | 고정된 처리 능력 안으로 들어오는 작업 수와 재시도 제어 | 서버 증설은 이 항목의 유입 제한 메커니즘을 대체하지 않는다. |
| C4 | 요청과 데이터의 분산을 통해 처리 범위를 넓히는 구조 | 요청 제한은 분산·확장 구조를 대체하지 않는다. 조회 복제본·캐시는 실제 점유 판정의 권위 있는 상태를 대체하지 않는다. |

## 검증 상태

작성 의도상 3-5는 Middle/Senior의 각 Criterion이 Pass하고, 4-1도 Pass하는 정상 대조군이다. 이는 작성자의 검토용 기대 판정이며, 사람 검토 완료 라벨이나 실제 Evaluator 측정값이 아니다. 골든·정상이라는 이름만으로 Pass를 강제하지 않는다. 다른 품질 평가 항목까지 모두 통과했다고 주장하지 않는다.

프로그램으로 확인한 사항: Middle 원본 바이트 일치, 두 파일의 공통 범위·NFR·평가 항목 동일, 배점 35·25·20·20(합계 100), Criterion별 Level 0~3 각 1개, 전체 32개 Level 서술 15~200자. 가장 긴 서술은 공백·문장부호 포함 142자다.

실제 LLM Evaluator는 호출하지 않았다. 기존 오류 주입 데이터는 이번 ZIP에 포함하지 않았다.
