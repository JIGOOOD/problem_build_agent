# 온라인 시험 답안 자동 저장 및 제출 서비스 설계

**설계 범위**
응시 중 답안 초안 자동 저장, 최종 제출과 중복 요청, 시험 마감 시점의 제출 판정, 동시 응시자 증가에 따른 저장 처리 확장을 설계한다. 문제 출제·채점·부정행위 탐지는 제외한다.

**평가 초점**
답안 보존과 최신 초안, 중복 제출 방지, 마감 시각 판정, 저장 요청 급증 처리

**대상 연차** Senior  
**배점** 100

| NFR | Criterion | 배점 |
|---|---|---:|
| NFR-1 · Consistency | C1. 초안 자동 저장과 복원 | 30 |
| NFR-2 · Fault Tolerance | C2. 최종 제출과 재시도 | 30 |
| NFR-3 · Consistency | C3. 마감 시각 판정 | 20 |
| NFR-4 · Throughput | C4. 자동 저장 부하 확장 | 20 |

## NFR-1. Consistency

**요구 수준**: 응시 중 저장 성공으로 확인된 답안은 재접속 후 복원할 수 있어야 하며, 이전 답안이 최신 저장본을 무심코 덮어써서는 안 된다.

### C1. 초안 자동 저장과 복원 · 30

**평가 항목**: 초안 덮어쓰기 경합과 저장 성공 판정 메커니즘을 평가한다.

| Level | 기준 |
|---|---|
| 0 | 저장 완료 전에 연결이 끊기거나 오래된 초안이 나중에 도착할 수 있다는 문제를 고려하지 않는다. |
| 1 | 응시자별 초안을 지속 저장한 뒤 성공 응답을 반환하고, 재접속 시 저장한 버전을 조회해 복원하는 기본 경로를 설명한다. 서로 다른 탭의 오래된 쓰기를 구분하는 방법은 설명하지 못한다. |
| 2 | 초안에 버전 번호를 부여하고 이전 버전과 일치할 때만 갱신하는 조건부 쓰기로 오래된 요청의 덮어쓰기를 막는다. 저장이 확정된 이후에만 성공 응답을 주고 버전 불일치에는 최신 초안을 다시 조회하도록 한다. |
| 3 | 2점에 더해, 빈번한 자동 저장의 동기 확인이 지연과 쓰기 부하를 늘리는 한계를 분석한다. 저장 간격과 조건부 쓰기 빈도를 조정하는 대안을 비교하고 초안 유실 위험·응답 지연·저장 비용의 상충에 따라 선택 근거를 설명한다. |

## NFR-2. Fault Tolerance

**요구 수준**: 최종 제출 요청이 재시도되더라도 같은 응시자의 제출 결과가 중복 생성되지 않고, 제출 완료 상태를 다시 확인할 수 있어야 한다.

### C2. 최종 제출과 재시도 · 30

**평가 항목**: 중복 요청의 동일 결과 반환과 제출 상태 확정 원리를 평가한다.

| Level | 기준 |
|---|---|
| 0 | 제출 요청 재시도와 완료 응답 유실로 같은 응시자의 제출이 중복 확정될 수 있다는 문제를 고려하지 않는다. |
| 1 | 중복 제출에는 멱등 키를 도입하거나 재시도를 제한하는 방안을 제안하지만, 최종 답안과 제출 완료 상태를 어떤 순서로 저장하고 응시자가 성공 여부를 어디서 확인하는지는 설명하지 못한다. |
| 2 | 응시자·시험별 제출 식별자를 사용하고 유일성 제약 또는 원자적 상태 전환으로 동시 중복 요청 중 하나만 제출 상태를 확정한다. 완료 응답이 유실돼 같은 요청이 재시도되면 이미 확정된 결과를 조회해 동일하게 반환한다. |
| 3 | 2점에 더해, 중복 확정을 막는 강한 쓰기 조정이 마감 직전 부하에서 대기를 늘리는 한계를 분석한다. 단일 제출 레코드의 원자적 갱신과 별도 중복 요청 기록 방식을 비교해 정합성·쓰기 경합·보관 비용을 근거로 선택한다. |

## NFR-3. Consistency

**요구 수준**: 시험 마감 전후의 제출 접수 여부를 모든 응시자에게 동일한 서버 기준으로 판정해야 한다.

### C3. 마감 시각 판정 · 20

**평가 항목**: 마감 경계 요청의 판정 순서와 동시성 처리를 평가한다.

| Level | 기준 |
|---|---|
| 0 | 서로 다른 서버의 시각이나 지연된 요청 때문에 마감 이후 제출이 허용될 수 있다는 문제를 고려하지 않는다. |
| 1 | 서버가 정한 마감 시각을 제출 접수 요청과 비교해 마감 전 요청만 저장하고, 마감 후에는 거절하는 기본 경로를 설명한다. 경계에서 동시 접수된 요청의 판정 일관성은 설명하지 못한다. |
| 2 | 마감 전후의 제출을 일관되게 처리할 트랜잭션 구조를 채택하고, 경계 시각에 동시에 들어오는 요청도 공정하게 승인하거나 거절하도록 관리하는 메커니즘을 설명한다. |
| 3 | 2점에 더해, 접수 시각과 완료 시각 사이의 차이나 분산 서버 시계 오차가 형평성과 처리 지연에 미치는 영향을 분석한다. 엄격한 서버 접수 기준과 제한적 유예 기준을 비교해 공정성·피크 처리량·운영 복잡도의 절충으로 선택을 정당화한다. |

## NFR-4. Throughput

**요구 수준**: 시험 시간대에 다수의 응시자가 동시에 자동 저장을 요청해도 저장 요청이 무한히 쌓이거나 성공한 저장이 소실되지 않아야 한다.

### C4. 자동 저장 부하 확장 · 20

**평가 항목**: 저장 수용량, 분할, 역압과 성공 응답의 안전한 경계를 평가한다.

| Level | 기준 |
|---|---|
| 0 | 동시에 자동 저장이 몰려 저장 대기열과 DB 쓰기가 병목이 되는 문제를 고려하지 않는다. |
| 1 | 여러 API가 저장 요청을 받아 내구성 있는 큐나 저장소에 기록한 후 성공을 응답하고, 작업자가 저장 내용을 반영하는 기본 경로를 설명한다. 저장 용량이 넘쳤을 때의 제한 방식은 설명하지 못한다. |
| 2 | 응시자 키로 작업을 분할해 서로 다른 응시자의 쓰기를 여러 작업자에 분산하고, 큐 길이와 저장 지연을 감시해 요청률을 제한하거나 재시도 지시로 역압을 건다. 성공 응답 전에 요청이 내구성 있게 보존되는 조건을 유지한다. |
| 3 | 2점에 더해, 대규모 시험의 특정 파티션에 요청이 집중되거나 과도한 역압으로 저장 성공까지의 시간이 늘어나는 한계를 분석한다. 분할 방식과 수용 제한 임계값을 비교해 지연·자원 비용·보존 보장의 상충에 따른 선택 근거를 설명한다. |
