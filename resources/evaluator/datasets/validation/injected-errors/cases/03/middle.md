# 온라인 시험 답안 자동 저장 및 제출 서비스 설계

**설계 범위**
응시 중 답안 초안 자동 저장, 최종 제출과 중복 요청, 시험 마감 시점의 제출 판정, 동시 응시자 증가에 따른 저장 처리 확장을 설계한다. 문제 출제·채점·부정행위 탐지는 제외한다.

**평가 초점**
답안 보존과 최신 초안, 중복 제출 방지, 마감 시각 판정, 저장 요청 급증 처리

**대상 연차** Middle  
**배점** 100

| NFR | Criterion | 배점 |
|---|---|---:|
| NFR-1 · Consistency | C1. 초안 자동 저장과 복원 | 30 |
| NFR-2 · Fault Tolerance | C2. 최종 제출과 재시도 | 30 |
| NFR-3 · Consistency | C3. 마감 시각 판정 | 20 |
| NFR-4 · Throughput | C4. 자동 저장 부하 확장 | 20 |

## NFR-1. Consistency

**요구 수준**: 응시 중 저장 성공으로 확인된 답안은 재접속 후 복원할 수 있어야 하며, 이전 답안이 최신 저장본을 무심코 덮어써서는 안 된다.

### C1. 초안 자동 저장과 복원 · 30

**평가 항목**: 답안 저장과 재접속 시 복원 경로를 평가한다.

| Level | 기준 |
|---|---|
| 0 | 응시 도중 연결이 끊기면 입력한 답안이 유실될 수 있다는 문제를 고려하지 않는다. |
| 1 | 답안을 주기적으로 저장하자고 제안하지만, 저장 요청을 어디서 받아 보관하고 재접속 때 어떻게 읽는지는 설명하지 못한다. |
| 2 | 브라우저가 변경된 답안을 저장 API로 보내고 서버가 응시자별 초안을 지속 저장한 뒤, 재접속 시 저장된 초안을 조회해 입력 화면을 복원하는 흐름을 설명한다. |
| 3 | 2점에 더해, 여러 탭에서 동시에 수정하면 이전 화면의 초안이 나중에 저장될 수 있음을 설명하고 마지막 저장 시각이나 버전을 보여 주어 충돌을 알리는 개선을 제시한다. |

## NFR-2. Fault Tolerance

**요구 수준**: 최종 제출 요청이 재시도되더라도 같은 응시자의 제출 결과가 중복 생성되지 않고, 제출 완료 상태를 다시 확인할 수 있어야 한다.

### C2. 최종 제출과 재시도 · 30

**평가 항목**: 제출 요청부터 저장된 제출 상태 조회까지의 기본 흐름을 평가한다.

| Level | 기준 |
|---|---|
| 0 | 제출 버튼을 여러 번 누르거나 응답이 유실되어 같은 제출 요청이 반복될 수 있다는 문제를 고려하지 않는다. |
| 1 | 최종 제출 결과를 서버에 보관하자고 제안하지만, 제출 답안과 제출 완료 상태를 어떤 순서로 저장하고 응시자가 어떻게 확인하는지 설명하지 못한다. |
| 2 | 최종 답안·제출 완료 상태 저장과 재접속 후 결과 조회 흐름을 설명한다. 이에 더해 동시 제출·응답 유실·처리 도중 장애가 겹치는 상황에서 멱등 키·원자적 상태 전환·중복 요청 보관을 결합하고, 여러 중복 제거 방식의 경합 비용과 복구 위험을 비교해 선택 근거를 제시한다. |
| 3 | 2점에 더해, 응답이 늦어 제출 버튼을 다시 누를 수 있음을 설명하고 이미 완료된 제출을 확인해 같은 결과를 보여 주는 기본 개선을 제시한다. |

## NFR-3. Consistency

**요구 수준**: 시험 마감 전후의 제출 접수 여부를 모든 응시자에게 동일한 서버 기준으로 판정해야 한다.

### C3. 마감 시각 판정 · 20

**평가 항목**: 제출 요청과 마감 시간 비교의 기본 흐름을 평가한다.

| Level | 기준 |
|---|---|
| 0 | 시험 종료 후 제출을 제한해야 한다는 문제를 고려하지 않는다. |
| 1 | 마감 시간이 지나면 제출을 막자고 제안하지만, 마감 여부를 어느 서버의 시간으로 어떻게 판단할지는 설명하지 못한다. |
| 2 | 제출 API가 서버 기준의 마감 시각과 요청 접수 시각을 비교하고, 마감 전 접수된 제출만 저장하며 마감 후 요청은 거절하는 흐름을 설명한다. |
| 3 | 2점에 더해, 사용자 기기 시각이 달라 마감 오해가 생길 수 있음을 설명하고 서버 기준 남은 시간을 화면에 안내하는 개선 방안을 제시한다. |

## NFR-4. Throughput

**요구 수준**: 시험 시간대에 다수의 응시자가 동시에 자동 저장을 요청해도 저장 요청이 무한히 쌓이거나 성공한 저장이 소실되지 않아야 한다.

### C4. 자동 저장 부하 확장 · 20

**평가 항목**: 다수 응시자의 자동 저장을 분산하고 보관하는 기본 경로를 평가한다.

| Level | 기준 |
|---|---|
| 0 | 다수 응시자의 자동 저장 요청이 한꺼번에 몰리는 문제를 고려하지 않는다. |
| 1 | 저장 서버를 늘리거나 큐를 사용하자고 제안하지만, 접수된 답안이 어떤 경로로 안전하게 보관되는지는 설명하지 못한다. |
| 2 | 로드밸런서가 여러 저장 API에 요청을 나누고, 각 API가 저장 요청을 지속 저장소 또는 내구성 있는 작업 큐에 기록한 뒤 성공을 반환하는 기본 흐름을 설명한다. |
| 3 | 2점에 더해, 같은 응시자가 짧은 시간에 연속 저장하면 불필요한 쓰기가 많아지는 한계를 설명하고 저장 주기를 조정하거나 연속 변경을 묶는 개선을 제시한다. |
