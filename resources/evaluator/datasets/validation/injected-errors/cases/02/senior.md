# 스마트 공장 센서 측정 모니터링 서비스 설계

**설계 범위**
센서 장치의 측정값 갱신 수집, 최근 측정값 조회, 센서를 보는 사용자에게 변경 전달, 접속이 끊긴 모니터링 사용자의 재연결을 설계한다. 기기 제어·설비 점검·이상 탐지 정책은 제외한다.

**평가 초점**
최신 측정값 반영, 대량 측정값 이벤트 처리, 다수 모니터링 사용자 전달, 재연결 복구

**대상 연차** Senior  
**배점** 100

| NFR | Criterion | 배점 |
|---|---|---:|
| NFR-1 · Consistency | C1. 최신 측정값 조회 | 30 |
| NFR-2 · Throughput | C2. 측정값 갱신 수집 | 25 |
| NFR-3 · Scalability | C3. 다수 모니터링 사용자 전달 | 25 |
| NFR-4 · Availability | C4. 재연결 후 측정값 복구 | 20 |

## NFR-1. Consistency

**요구 수준**: 늦게 도착한 오래된 측정값으로 최근 측정값이 덮이지 않도록 하면서, 이용자가 센서의 최근 측정값을 지연 없이 조회할 수 있어야 한다.

### C1. 최신 측정값 조회 · 30

**평가 항목**: 늦게 도착한 갱신의 역전 방지와 조회 일관성의 처리 원리를 평가한다.

| Level | 기준 |
|---|---|
| 0 | 오래된 측정값이 나중에 도착해 최신 측정값을 덮어쓸 수 있다는 문제를 고려하지 않는다. |
| 1 | 장치의 측정값 이벤트를 받아 센서별 최신 측정값과 관측 시각을 저장하고, 조회 요청에 보관된 측정값을 반환하는 정상 처리 흐름을 설명한다. 늦게 도착한 이전 측정값의 갱신 순서를 판단하는 원리는 설명하지 못한다. |
| 2 | 센서별 단조 증가 갱신 번호 등 순서를 판정할 기준을 유지하고, 저장된 번호보다 오래된 이벤트는 최근 측정값을 덮지 못하게 조건부 갱신한다. 조회는 마지막으로 승인된 측정값을 반환하며 갱신 역전과 오래된 측정값 문제에 대응한다. |
| 3 | 2점에 더해, 이벤트 재전송과 장치 재시작으로 갱신 번호가 초기화될 위험을 분석한다. 장치 세션별 번호 관리와 관측 시각 기반 판정의 장단점을 비교해 시계 오류·재전송 비용·정확성에 따른 선택 근거를 설명한다. |

## NFR-2. Throughput

**요구 수준**: 많은 센서가 짧은 간격으로 측정값을 보내도 수집 요청이 계속 적체되지 않고 최근 측정값을 갱신해야 한다.

### C2. 측정값 갱신 수집 · 25

**평가 항목**: 이벤트 처리 분할·역압 제어와 처리량·최신성의 상충을 평가한다.

| Level | 기준 |
|---|---|
| 0 | 측정값 갱신 유입이 증가할 때 수집 처리량과 작업 적체 문제를 고려하지 않는다. |
| 1 | 수집 서버가 측정값 이벤트를 접수하고 비동기 작업자에게 전달해 센서별 최신 측정값을 저장하는 기본 경로를 설명한다. 처리량 초과 시 큐 적체를 제어하는 방식은 설명하지 못한다. |
| 2 | 이벤트 수집 계층을 수평 확장하고 비동기 작업자 기반의 유연한 처리 파이프라인을 구성해 유입 부하를 효율적으로 분산하며, 적체를 관리하고 병목을 최소화하는 설계를 설명한다. |
| 3 | 2점에 더해, 특정 센서 갱신이 한 파티션에 집중되거나 과도한 병합이 측정값 최신성을 낮추는 한계를 분석한다. 분할 단위와 병합·제한 임계값을 비교하고 수집 지연·손실 위험·운영 비용의 상충으로 선택을 설명한다. |

## NFR-3. Scalability

**요구 수준**: 특정 센서를 동시에 지켜보는 모니터링 사용자가 증가해도 한 전달 서버에 모든 연결과 측정값 알림이 집중되지 않아야 한다.

### C3. 다수 모니터링 사용자 전달 · 25

**평가 항목**: 구독 상태와 팬아웃 분산, 느린 연결에 대한 대응을 평가한다.

| Level | 기준 |
|---|---|
| 0 | 센서별 모니터링 사용자가 급증할 때 한 전달 서버의 연결·전송 부하가 병목이 되는 문제를 고려하지 않는다. |
| 1 | 센서별 구독을 유지하고 새 측정값이 도착하면 해당 센서를 보는 연결에 변경을 보내는 기본 경로를 설명한다. 모니터링 사용자가 한 서버의 전송 용량을 넘길 때의 처리 메커니즘은 설명하지 못한다. |
| 2 | 동일 센서의 모니터링 사용자 연결도 여러 전달 서버에 분산하고, 구독 경로를 통해 각 서버에 측정값 갱신을 전달한다. 느린 모니터링 사용자 연결의 전송 대기가 다른 연결을 막지 않도록 연결별 버퍼나 최신값 교체 등 격리 방안을 설명한다. |
| 3 | 2점에 더해, 팬아웃 확장 시 발생하는 다양한 문제를 심층 분석하고 트레이드오프를 종합적으로 고려해 최적의 전달 구조를 선택한다. |

## NFR-4. Availability

**요구 수준**: 모니터링 사용자의 연결이 끊겨도 재접속 후 센서의 최근 측정값을 다시 확인할 수 있어야 한다.

### C4. 재연결 후 측정값 복구 · 20

**평가 항목**: 재연결 중 누락 방지와 복구 이력 유지 비용을 평가한다.

| Level | 기준 |
|---|---|
| 0 | 모니터링 사용자의 접속이 끊긴 뒤 현재 측정값과 후속 갱신을 다시 확보해야 한다는 문제를 고려하지 않는다. |
| 1 | 센서별 현재 측정값을 지속 저장하고, 재접속 시 보관된 측정값을 받아 다시 실시간 변경을 구독하는 흐름을 설명한다. 재구독 사이에 빠진 변경의 처리 원리는 설명하지 못한다. |
| 2 | 재접속 시 저장된 마지막 수신 갱신 번호를 기준으로 누락 이벤트를 재전송하거나, 복구 이력이 없으면 최신 스냅샷과 그 이후의 변경을 연결해 이어받는다. 스냅샷과 구독 전환 사이에 누락이 생기지 않도록 기준 갱신 번호를 사용한다. |
| 3 | 2점에 더해, 긴 이력 보관은 비용을 늘리고 짧은 보관은 스냅샷 복구 빈도를 늘리는 한계를 분석한다. 보관 기간과 스냅샷 주기를 비교해 저장 비용·복구 대역폭·복구 지연의 상충을 설명한다. |
