# 스마트 공장 센서 측정 모니터링 서비스 설계

**설계 범위**
센서 장치의 측정값 갱신 수집, 최근 측정값 조회, 센서를 보는 사용자에게 변경 전달, 접속이 끊긴 모니터링 사용자의 재연결을 설계한다. 기기 제어·설비 점검·이상 탐지 정책은 제외한다.

**평가 초점**
최신 측정값 반영, 대량 측정값 이벤트 처리, 다수 모니터링 사용자 전달, 재연결 복구

**대상 연차** Middle  
**배점** 100

| NFR | Criterion | 배점 |
|---|---|---:|
| NFR-1 · Consistency | C1. 최신 측정값 조회 | 30 |
| NFR-2 · Throughput | C2. 측정값 갱신 수집 | 25 |
| NFR-3 · Scalability | C3. 다수 모니터링 사용자 전달 | 25 |
| NFR-4 · Availability | C4. 재연결 후 측정값 복구 | 20 |

## NFR-1. Consistency

**요구 수준**: 늦게 도착한 오래된 측정값으로 최근 측정값이 덮이지 않도록 하면서, 이용자가 센서의 최근 측정값을 지연 없이 조회할 수 있어야 한다.

### C1. 최신 측정값 조회 · 30

**평가 항목**: 측정값 수집부터 최근 측정값 조회까지의 기본 데이터 흐름을 평가한다.

| Level | 기준 |
|---|---|
| 0 | 오래된 측정값이 최신 측정값처럼 조회될 수 있다는 문제를 고려하지 않는다. |
| 1 | 센서가 보낸 측정값을 서버에 저장해 조회하는 방안을 제안하지만, 수집한 측정값이 저장소와 조회 화면까지 전달되는 역할과 흐름을 설명하지 못한다. |
| 2 | 장치·수집 서버·최근 측정값 저장소·조회 서버의 처리 흐름을 설명한다. 이에 더해 장치 시계 오류, 재시작 후 번호 초기화, 순서가 뒤바뀐 재전송이 함께 발생할 때의 정합성을 분석하고, 세션별 번호와 관측 시각을 사용하는 대안의 지연·오판 위험·처리 비용을 비교해 선택 근거를 제시한다. |
| 3 | 2점에 더해, 일정 시간 갱신되지 않은 측정값이 현재 측정값으로 오인될 수 있음을 설명하고 마지막 수신 시간을 표시하거나 오래된 측정값임을 알려 주는 개선 방안을 제시한다. |

## NFR-2. Throughput

**요구 수준**: 많은 센서가 짧은 간격으로 측정값을 보내도 수집 요청이 계속 적체되지 않고 최근 측정값을 갱신해야 한다.

### C2. 측정값 갱신 수집 · 25

**평가 항목**: 대량 수집 요청의 역할 분리와 저장 흐름을 평가한다.

| Level | 기준 |
|---|---|
| 0 | 측정값 전송이 몰릴 때 수집 처리량이 부족해질 수 있다는 문제를 고려하지 않는다. |
| 1 | 측정값 이벤트를 비동기로 처리하자고 제안하지만, 이벤트 접수와 실제 저장을 담당하는 구성요소의 역할이나 처리 순서를 설명하지 못한다. |
| 2 | 수집 서버가 측정값 이벤트를 접수해 큐에 전달하고, 여러 작업자가 이벤트를 읽어 센서별 최근 측정값을 저장하는 흐름을 설명한다. |
| 3 | 2점에 더해, 저장 요청이 몰리면 큐가 길어져 측정값 반영이 늦어질 수 있음을 설명하고 짧은 시간에 몰린 동일 센서 갱신을 묶어 저장하는 개선을 제시한다. |

## NFR-3. Scalability

**요구 수준**: 특정 센서를 동시에 지켜보는 모니터링 사용자가 증가해도 한 전달 서버에 모든 연결과 측정값 알림이 집중되지 않아야 한다.

### C3. 다수 모니터링 사용자 전달 · 25

**평가 항목**: 측정값 갱신을 구독 사용자에게 전달하는 기본 구조를 평가한다.

| Level | 기준 |
|---|---|
| 0 | 모니터링 사용자가 많아질 때 동일한 측정값 갱신을 여러 사용자에게 전달해야 한다는 문제를 고려하지 않는다. |
| 1 | 측정값이 바뀌면 사용자에게 푸시로 알리자고 제안하지만, 어떤 서버가 구독 대상을 찾고 메시지를 전달하는지 설명하지 못한다. |
| 2 | 모니터링 사용자의 센서 구독을 전달 서버가 관리하고, 수집된 새 측정값을 해당 센서를 보는 사용자 연결에 전송하는 흐름을 설명한다. |
| 3 | 2점에 더해, 종료된 연결이 구독 목록에 계속 남으면 불필요한 전달이 늘어나는 한계를 설명하고 끊어진 구독을 정리하는 개선을 제시한다. |

## NFR-4. Availability

**요구 수준**: 모니터링 사용자의 연결이 끊겨도 재접속 후 센서의 최근 측정값을 다시 확인할 수 있어야 한다.

### C4. 재연결 후 측정값 복구 · 20

**평가 항목**: 접속 복구와 최근 상태 확보의 기본 흐름을 평가한다.

| Level | 기준 |
|---|---|
| 0 | 모니터링 사용자 연결이 끊긴 뒤 측정값 화면을 복구해야 한다는 문제를 고려하지 않는다. |
| 1 | 재연결 시 측정값을 다시 조회하는 방안을 제시하지만, 현재 측정값을 어디에 보존하고 어떤 경로로 다시 받는지 설명하지 못한다. |
| 2 | 서버가 센서별 최근 측정값을 보관하고, 모니터링 사용자가 재접속하면 보관된 현재 측정값을 다시 조회한 뒤 실시간 수신을 이어가는 흐름을 설명한다. |
| 3 | 2점에 더해, 재접속 중 구독 갱신이 늦으면 측정값 표시가 잠시 오래될 수 있음을 설명하고 현재 측정값을 다시 확인해 화면을 갱신하는 개선 방안을 제시한다. |
