# YouTube 동영상 업로드 및 스트리밍

**설계 범위**
대용량 동영상 업로드, 원본 저장과 형식 변환·세그먼트 생성, 중단된 업로드 재개, 영상 스트리밍 및 대규모 시청 요청 분산까지 설계한다. 검색·추천·댓글·구독은 제외한다.

**평가 초점**
업로드 중단 후 재개, 저대역폭 환경의 끊김 없는 재생, 대량 영상 변환 작업 처리, 대규모 시청 트래픽 분산

**대상 연차** Senior\

## NFR-1. Low Latency

**요구 수준**
`latency` — 시스템은 느리거나 변동이 큰 네트워크에서도 재생 시작을 지연시키지 않고, 전송 가능한 화질을 조정해 버퍼링을 줄여야 한다.

### C1. 세그먼트 기반 적응형 스트리밍 · 35

**평가 항목**
세그먼트·매니페스트·비트레이트 선택 메커니즘과 화질·재생 지연·전송 오버헤드의 Trade-off를 평가한다.

| Level | 기준 |
| --- | --- |
| 0 | 전체 영상 다운로드로 발생하는 시작 지연과 변동하는 대역폭에 따른 재생 중단을 고려하지 않는다. |
| 1 | 서버가 화질별 세그먼트 주소를 재생 목록(매니페스트)으로 제공하고, 플레이어가 목록을 따라 필요한 부분을 순서대로 요청해 재생하는 경로를 설명한다. 여러 화질 중 선택은 가능하지만 전송 속도와 남은 버퍼를 확인해 재생 중 화질을 전환하는 조건은 설명하지 못한다. |
| 2 | 여러 화질로 인코딩한 영상의 세그먼트 URL을 매니페스트로 제공한다. 플레이어가 선택한 화질의 세그먼트를 순서대로 받고 버퍼링한다. 전송 속도와 남은 버퍼를 확인해 낮은 화질로 전환하는 등 대역폭 하락 시 재생 중단에 대응한다. |
| 3 | 2점에 더해, 순간적인 전송 속도 변화에 반응하면 화질 전환이 잦아지고 짧은 세그먼트는 요청 오버헤드를 늘림을 분석한다. 비트레이트 전환 기준과 세그먼트 길이를 비교하고, 화질·재생 지연·전환 빈도·저장 비용의 Trade-off로 선택을 정당화한다. |

## NFR-2. High Throughput

**요구 수준**
`throughput` — 시스템은 대량으로 업로드되는 동영상을 여러 재생 형식으로 변환하되, 긴 인코딩 작업으로 변환 대기열이 계속 누적되지 않도록 처리해야 한다.

### C2. 대규모 동영상 변환 작업 처리 · 25

**평가 항목**
비동기 세그먼트 인코딩 작업의 분산·의존성 처리와 업로드-변환 파이프라인의 처리량·지연 Trade-off를 평가한다.

| Level | 기준 |
| --- | --- |
| 0 | 대량의 업로드 영상에 대해 형식 변환 작업의 처리량과 병목을 고려하지 않는다. |
| 1 | 원본 저장 후 업로드 요청에서 변환을 분리해 비동기 작업으로 전달하고, 변환 워커가 원본을 읽어 재생 형식별 결과를 저장하는 처리 경로를 설명한다. 다만 변환 작업의 진행 상태를 기록하거나 실패한 작업을 재실행하는 방식은 설명하지 못한다. |
| 2 | 원본을 객체 저장소에 저장하고 형식·화질별 변환을 별도 비동기 워커에 분산한다. 작업 상태를 기록하고 완료된 결과를 저장하며, 실패한 변환을 재실행해 업로드 처리와 변환을 분리한다. |
| 3 | 2점에 더해, 긴 영상을 한 작업으로 변환하면 작업자가 오래 점유되어 대기열이 늘어나는 한계를 분석한다. 영상 단위 변환과 세그먼트·화질별 병렬 변환을 비교해 작업 의존성·부분 실패 재실행·관리 오버헤드와 처리량의 상충을 설명하고, 영상 길이와 작업 유입량에 따른 작업 단위 선택 근거를 제시한다. |

## NFR-3. High Availability

**요구 수준**
`availability` — 시스템은 대용량 동영상 업로드가 네트워크 문제로 중단되어도 이미 업로드한 부분을 유지하고 나머지 부분부터 재개할 수 있어야 한다.

### C3. 대용량 업로드 중단 후 재개 · 20

**평가 항목**
멀티파트 업로드 세션·완료 상태 확인 메커니즘과 중복 완료·미완료 부분 관리 및 관련 Trade-off를 평가한다.

| Level | 기준 |
| --- | --- |
| 0 | 대용량 업로드 중단 시 이미 전송한 데이터를 보존하고 복구해야 한다는 문제를 고려하지 않는다. |
| 1 | 업로드 ID와 부분 번호로 한 파일의 조각을 식별하고, 재접속한 클라이언트가 같은 업로드 세션에서 완료된 부분을 제외하고 전송하는 복구 경로를 설명한다. 다만 저장소의 실제 완료 목록을 확인해 기록과 대조하거나 부분을 검증·조립하는 절차는 설명하지 못한다. |
| 2 | 업로드 ID와 부분 번호로 멀티파트 세션을 관리하고 각 부분을 객체 저장소에 직접 업로드한다. 완료 목록과 ETag를 확인해 누락분만 전송한 뒤 검증·조립한다. |
| 3 | 2점에 더해, 재시도나 중복 완료 요청으로 업로드 상태가 어긋날 위험을 분석한다. 완료 처리의 멱등성·미완료 세션 정리를 제시하고, 작은 부분과 큰 부분의 재전송량·요청 오버헤드·관리 복잡성을 비교해 파일 크기와 네트워크 불안정성에 따른 부분 크기 선택 근거를 설명한다. |

## NFR-4. High Scalability

**요구 수준**
`scalability` — 시스템은 대규모 시청자가 동일한 영상을 동시에 요청하더라도 원본 저장소에 읽기 부하가 집중되지 않도록 콘텐츠 전달 경로를 확장해야 한다.

### C4. 대규모 영상 시청 요청 분산 · 20

**평가 항목**
CDN 캐시·원본 저장소의 요청 분산 메커니즘과 캐시 적중률·지연·전송 비용의 Trade-off를 평가한다.

| Level | 기준 |
| --- | --- |
| 0 | 동시 시청자가 증가할 때 영상 전송과 원본 저장소의 읽기 용량을 어떻게 확장할지 고려하지 않는다. |
| 1 | 요청한 영상·화질·세그먼트를 구분해 CDN 엣지의 캐시 적중 여부를 판단하고, 적중 시 바로 전달하며 미스 시 원본에서 가져와 캐시에 채우는 경로를 설명한다. 다만 같은 세그먼트의 동시 캐시 미스로 원본에 중복 요청이 몰리는 경우는 제어하지 못한다. |
| 2 | CDN 엣지에서 영상 세그먼트를 캐시하고, 캐시 미스일 때만 원본 저장소에서 가져오도록 한다. 지역별 엣지를 활용해 원본 읽기 요청과 시청자까지의 전송 지연을 줄인다. 같은 세그먼트의 동시 캐시 미스는 원본 조회를 합치고 결과를 공유하는 등 원본으로 몰리는 중복 요청에 대응한다. |
| 3 | 2점에 더해, 인기 영상과 드물게 시청하는 영상의 캐시 적중률·보관 비용 차이를 분석한다. 캐시 유지 정책에 따른 원본 부하·지역별 지연·CDN 비용의 Trade-off를 설명하고 선택을 정당화한다. |
