# 연차별 루브릭 생성·채점 기준

## Level별 기준

| Level | Middle | Senior |
|---|---|---|
| 0 | 핵심 설계 문제를 고려하지 않는다. | 핵심 설계 문제를 고려하지 않는다. |
| 1 | 문제를 인식하고 기본적인 해결 방안을 제시하지만, 주요 컴포넌트의 역할이나 처리 흐름을 충분히 설명하지 못한다. | 핵심 요구사항을 정상 처리 흐름에서 충족하는 기본 설계를 제시하지만, 관련된 주요 동시성·장애·병목 상황에서 보장을 유지하는 구체적인 처리 방법은 설명하지 못한다. |
| 2 | 핵심 요구사항을 충족하는 주요 컴포넌트의 역할과 기본 처리 흐름을 설명한다. 기본 흐름에 필요한 조건은 포함하되, 서로 독립적인 복수의 예외 상황에 대한 대응까지 필수로 요구하지 않는다. | 기본 설계를 바탕으로 핵심 요구사항을 보장하는 구체적인 기술적 메커니즘과 동작 조건을 설명하고, 해당 설계와 관련된 주요 문제 상황에 대응하는 처리 흐름을 제시한다. |
| 3 | 2점에 더해, 대표적인 한계와 그에 연결된 기본 개선 방안을 설명한다. 복잡한 상황의 교차 분석이나 대안 간 Trade-off는 요구하지 않는다. | 2점에 더해, 설계의 주요 한계와 복잡한 상황을 분석하고, 기술적 선택의 Trade-off와 선택 근거를 설명한다. |

| 난이도 | Middle | Senior |
|---|---|---|
| 가장 낮음 | Level 0: 문제 미고려 | Level 0: 문제 미고려 |
| 낮음 | Level 1: 미흡한 해결 시도 | — |
| 중간 | Level 2: 동작하는 기본 설계 | Level 1: 동작하는 기본 설계 |
| 높음 | Level 3: 대표적 한계 개선 | Level 2: 구체적 메커니즘과 주요 문제 대응 |
| 가장 높음 | — | Level 3: 복잡한 상황과 Trade-off 분석 |

## 공통 생성 규칙

1. 각 Level은 이전 Level보다 높은 설계 역량을 요구해야 한다.
2. Middle은 문제 인식과 미흡한 해결 시도 → 동작하는 설계 → 대표적인 한계 개선으로 발전한다. Senior는 동작하는 기본 설계 → 구체적인 기술적 메커니즘과 주요 문제 대응 → 설계의 한계·복잡한 상황 분석 및 Trade-off와 선택 근거로 발전한다.
3. 연차에 따라 기술 이름이나 설명 길이만 변경하지 않고, 요구하는 기술적 깊이와 문제 해결 범위를 실질적으로 변경한다.
4. Middle은 기본 설계와 대표적인 문제 해결을, Senior는 구체적인 구현 메커니즘과 심층 분석 및 기술적 의사결정을 중심으로 평가한다.
5. 모든 Criterion에 동시성, 장애, 병목을 일괄적으로 요구하지 않는다. 해당 평가 항목과 관련 있는 문제만 다룬다.
6. 특정 기술 사용 여부보다 요구사항을 충족하는 설계의 타당성을 우선 평가한다.
7. Middle 3점은 2점 설계의 대표적인 한계와 개선 방안을 요구한다. Senior 3점은 2점 설계를 바탕으로 주요 한계·복잡한 상황과 Trade-off를 분석하고 선택 근거를 설명하도록 한다. Senior 2점에서 별도의 한계 분석을 필수로 요구하지 않는다. ‘구체적인 메커니즘’, ‘심층 분석’, ‘Trade-off’라는 표현만으로 난이도를 높이지 않는다. Middle 3점과 Senior 2점의 기술이나 해결 방법을 같게 맞출 필요는 없다.
8. Middle 2점은 해당 NFR의 핵심 요구를 충족하는 기본 구성과 처리 흐름, 이를 성립시키는 최소한의 조건까지만 필수로 요구한다. 장애 복구처럼 실패 대응 자체가 핵심 흐름인 경우 그 기본 복구 흐름은 포함할 수 있다. 다만 복수의 독립적인 경합·장애·병목 상황 각각에 대한 대응 정책이나 복잡한 보장 조건을 모두 필수로 요구하지 않는다. Senior 2점은 해당 NFR과 관련된 주요 문제에서 보장을 유지하는 구체적인 기술적 메커니즘·동작 조건·처리 원리를 요구한다.
9. 연차 간 상대적 난이도는 Middle 2점 ≈ Senior 1점, Middle 3점 ≈ Senior 2점을 참고한다. 이는 요구하는 설계 역량의 대략적인 수준을 나타내며, 동일한 기술·해결 방법·채점 조건을 의미하지 않는다. Senior는 유사한 문제 해결 수준에서도 더 구체적인 메커니즘과 주요 문제 대응을 요구하며, Senior 3점은 복잡한 상황 분석과 Trade-off 및 선택 근거까지 평가한다.

## 평가기 채점 규칙

1. **3-5는 절대 평가한다.** Middle 각 Level은 Middle 기준으로, Senior 각 Level은 Senior 기준으로 별도 판정한다. 상대 연차의 루브릭을 정답으로 가정하지 않는다.
2. **필수 요구의 깊이와 범위를 함께 본다.** 특정 기술이나 예외 상황이 언급됐다는 이유만으로 Fail하지 않는다. 해당 Level에서 반드시 설명해야 하는 구성·동작·문제 대응을 확인한다. 기본 흐름의 성립에 필요한 조건과 독립적인 여러 예외 대응의 필수화를 구분한다.
3. **Middle 2점의 경계를 확인한다.** 기본 설계를 넘어 여러 독립적인 실패 상황 각각의 대응을 필수화하거나, 구체적인 보장 메커니즘·비용 비교를 요구하면 Fail한다.
4. **Middle 3점의 경계를 확인한다.** 대표적인 한계와 기본 개선은 인정하되, 복잡한 상황의 상호작용 분석이나 대안 간 Trade-off를 필수화하면 Fail한다. `2점에 더해`로 부적합한 Level 2 요구를 상속한 경우에도 Fail이며, 원인인 Level 2와 연쇄 영향을 구분한다.
5. **Senior 2·3점의 경계를 확인한다.** Senior 2점은 주요 문제에 대한 처리 조건·메커니즘·동작 원리가 있어야 한다. 결과만 보장하겠다고 하거나 기본 흐름을 반복한다면 Fail한다. Senior 3점은 복잡한 상황과 한계, 대안의 이득·비용 및 선택 근거를 실질적으로 요구해야 한다. 특정 알고리즘·제품명·코드는 강제하지 않는다.
6. **4-1은 상대 평가한다.** 대응되는 설계 문제를 맞춘 뒤 Senior가 요구하는 추가 역량을 비교한다. 4-1 Fail이라고 해서 Middle과 Senior의 3-5를 자동으로 모두 Fail 처리하지 않는다. 각 연차가 절대 기준을 충족했는지는 별도로 판단한다.

## Ticket 예시: 주문 장애 복구(C2)

아래는 **요구 깊이의 예시**이며, 특정 구현이나 문장을 반드시 사용하라는 뜻이 아니다.

| 수준 | 적절한 필수 요구의 예시 |
|---|---|
| Middle 2 / Senior 1 | 주문을 접수 성공 전에 저장하고, 장애 후 미완료 주문을 찾아 재개해 완료 상태를 기록하는 기본 흐름 |
| Middle 3 | 재처리로 중복 확정될 수 있는 대표적인 한계를 짚고, 기존 처리 결과를 확인하는 기본 개선 |
| Senior 2 | 주문 식별자·확정 기록·중복 통지에 대한 구체적인 판정 조건과 처리 원리, 외부 결제 결과 불명 시의 대응 메커니즘 |
| Senior 3 | 외부 결제 성공·내부 기록 실패 등 복잡한 상황을 분석하고, 복구·대사 대안의 지연·조회 비용과 선택 근거를 설명 |

Middle 2점에서 기본 보존·재개와 별개로 **중복 이벤트, 외부 결제 결과 불명, 좌석 재할당 충돌 각각의 복구 정책**을 모두 필수화하면 요구 범위가 과도할 수 있다. 반대로 그 단어들이 예시로 등장했다는 사실만으로는 Fail이 아니다.
