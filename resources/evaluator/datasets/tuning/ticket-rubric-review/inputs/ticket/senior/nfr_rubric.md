# 공연 좌석 티켓 예매

**설계 범위**
공연별 좌석 잔여 현황 조회, 좌석 임시 점유와 만료, 주문 생성과 외부 결제 결과에 따른 예매 확정 또는 해제까지 설계한다. 결제 대행사 내부 구현·환불·재판매·공연 추천은 제외한다.

**평가 초점**
동일 좌석의 중복 예매 방지, 점유 만료·지연 결제 응답·재시도의 상태 일관성, 예매 오픈 시 조회·점유 요청 폭증 대응, 접수된 주문의 장애 후 복구와 중복 확정 방지

**대상 연차** Senior\
**배점** 100

## NFR-1. Consistency

**요구 수준**
`consistency` — 동시 요청 중 동일 좌석의 유효한 소유자는 하나만 존재한다. 만료된 점유나 이전 소유자의 결제·해제 요청은 현재 점유 또는 확정을 변경하지 못한다. 동일 요청의 재시도는 새로운 점유나 확정을 만들거나 원래 만료를 임의로 연장하지 않는다. 잔여 좌석 조회에는 일시적인 지연을 허용할 수 있지만 점유·확정 판단은 현재 상태를 검증한다.
동일 좌석의 유효한 점유와 예매 확정은 배타적이어야 하며, 만료·지연 결제 결과·재시도가 경합해도 현재 소유권과 상태에 맞는 전이만 허용해야 한다.

### C1. 좌석 소유권과 상태 전이의 일관성 · 35

**평가 항목**
좌석 점유·만료·확정·해제의 정상 처리와 경합에서 현재 소유권을 보장하는 상태 전이 및 요청 재시도 처리를 평가하며, 장애 후 주문 복구 절차는 제외한다.

| Level | 기준 |
|---|---|
| 0 | 동일 좌석의 동시 점유나 만료·결제 결과의 경합에 따른 잘못된 상태 전이를 고려하지 않는다. |
| 1 | 좌석의 배타적 점유와 확정 흐름을 제시하지만, 소유권·만료 검증을 상태 변경과 결합하는 방법이나 지연 요청·재시도의 처리 방안을 구체적으로 설명하지 못한다. |
| 2 | 현재 소유권·상태·만료를 검증하며 배타적으로 전이하는 메커니즘을 설명한다. 이전 점유의 결제·해제가 새 소유권을 바꾸지 못하고, 동일 요청 재시도가 새 점유·확정이나 만료 연장을 만들지 않도록 처리한다. 조회가 지연되어도 점유·확정은 현재 상태로 판단한다. |
| 3 | 2점에 더해, 만료 판정과 재점유 사이에 이전 결제·해제가 끼어드는 경합을 추적하여 설계의 빈틈을 분석한다. 검증 경계나 전이 순서의 개선을 제시하고, 배타성을 유지하면서 경합 대기 또는 재시도 부담을 조정한 선택 근거를 설명한다. |

## NFR-2. Fault Tolerance

**요구 수준**
`fault_tolerance` — 접수된 주문은 재시작 후 식별하고 처리를 재개하거나 결과를 조정할 수 있다. 외부 결제 결과가 불명확하면 새 작업으로 재실행하지 않고 기존 작업과 대조한다. 중복 전달과 재처리는 같은 주문의 확정을 중복 반영하지 않으며, 지연된 성공 결과도 현재 좌석의 유효한 소유권을 침해하지 않는다.
접수된 주문과 결제 처리의 진행 상태는 프로세스 장애 이후 복구할 수 있어야 하며, 결과 불명·재전달·재시도로 중복 결제 시도나 중복 예매 확정이 발생하지 않아야 한다.

### C2. 접수된 주문과 결제 진행 상태의 복구 · 25

**평가 항목**
주문 접수 이후 장애와 외부 결제 결과 불명 상황에서 지속 상태를 바탕으로 처리 재개·결과 대조·중복 반영 방지를 수행하는 복구 경로를 평가하며, 좌석 전이 자체의 배타성은 제외한다.

| Level | 기준 |
|---|---|
| 0 | 접수 후 프로세스 장애나 결제 결과 유실로 주문의 진행 상태를 잃을 수 있다는 문제를 고려하지 않는다. |
| 1 | 주문 상태를 저장하고 실패한 처리를 재시도하는 흐름은 제시하지만, 재시작 후 처리 대상 식별이나 결제 결과 불명·중복 전달에 대한 구체적인 복구 방법을 설명하지 못한다. |
| 2 | 접수된 주문의 진행 상태와 외부 작업 식별 정보를 지속 보존하고 재시작 후 재개 대상을 찾는 흐름을 설명한다. 결과 불명은 기존 결제와 대조하고, 재전달·재처리의 중복 확정을 막으며, 지연 성공도 현재 좌석 소유권 검증을 거치게 한다. |
| 3 | 2점에 더해, 외부 결제는 성공했으나 로컬 기록 전 장애가 나거나 복구 작업과 결과 수신이 겹치는 상황을 추적한다. 복구의 중복·누락 가능성을 줄이는 조정 방안과, 재시도보다 결과 대조를 선택하는 조건 및 처리 지연의 상충을 설명한다. |

## NFR-3. High Throughput

**요구 수준**
`throughput` — 조회·점유·주문 부하 조건을 구분하여 지속 가능한 처리 용량을 검증하고, 초과 유입이 핵심 처리 경로에 무제한 전달되지 않게 한다. 부하가 용량을 넘으면 명시적인 대기 또는 제한 결과를 제공하며, 구체적인 허용 유입률과 동시 사용자 수는 부하 검증 후 정한다.
예매 오픈 시 유입량이 처리 능력을 초과하더라도 점유·주문 경로에 전달되는 작업량을 감당 가능한 범위로 제한하여 과부하의 연쇄 전파를 방지해야 한다.

### C3. 검증된 처리 용량에 따른 초과 유입 통제 · 20

**평가 항목**
예매 오픈 시 조회·점유·주문별 처리 용량 검증과 초과 유입의 대기·제한으로 핵심 경로를 보호하는 판단을 평가하며, 자원 추가를 통한 처리 범위 확장은 제외한다.

| Level | 기준 |
|---|---|
| 0 | 유입량이 처리 능력을 초과할 때 점유·주문 경로로 작업이 무제한 전달되는 문제를 고려하지 않는다. |
| 1 | 대기나 요청 제한으로 폭증을 제어하는 기본 설계를 제시하지만, 제한 기준을 처리 용량과 연결하거나 실제 점유·주문 경로까지 전달되는 작업량을 통제하는 방법을 설명하지 못한다. |
| 2 | 조회·점유·주문 부하를 구분한 부하 검증 방법과 그 결과로 유입 한도를 정하는 절차를 설명한다. 핵심 경로에 전달되는 작업량을 제한하고, 초과 요청에는 명시적인 대기 또는 제한 결과를 제공하여 연쇄 과부하를 막는다. |
| 3 | 2점에 더해, 고정 유입 한도가 처리 용량 변화나 재시도 증가를 반영하지 못하는 한계를 분석한다. 적체와 처리 상태를 관찰하여 유입을 조정하는 개선을 제시하고, 보호 강도를 높일 때 늘어나는 대기 또는 제한과 처리 용량 활용 사이의 선택 근거를 설명한다. |

## NFR-4. Scalability

**요구 수준**
`scalability` — 조회 부하의 증가가 점유·확정 경로에 그대로 전파되지 않고, 서로 다른 좌석에 대한 작업은 처리 자원을 늘려 수용 범위를 확대할 수 있다. 특정 공연의 집중 부하와 동일 좌석 경합을 별도로 설명하며, 자원 추가만으로 동일 좌석의 배타적 처리 한계가 사라진다고 가정하지 않는다.
조회량과 여러 좌석에 대한 점유량이 증가할 때 처리 범위를 확장할 수 있어야 하며, 특정 공연이나 좌석으로 집중되는 경합의 한계를 구분해야 한다.

### C4. 조회·점유 경로의 확장과 집중 경합의 한계 · 20

**평가 항목**
조회와 점유의 부하 분리 및 서로 다른 좌석 작업의 처리 범위 확장을 평가하고, 특정 공연 집중과 동일 좌석 경합을 구분하되 초과 유입의 대기·제한 정책은 제외한다.

| Level | 기준 |
|---|---|
| 0 | 조회량과 여러 좌석의 점유량 증가에 따라 처리 범위를 확장해야 한다는 문제를 고려하지 않는다. |
| 1 | 조회 부하 분리나 처리 자원 증설을 제시하지만, 서로 다른 좌석의 작업을 어떻게 분산하는지 설명하지 못하거나 자원 추가로 동일 좌석 경합도 해소된다고 가정한다. |
| 2 | 조회 부하가 점유·확정 경로에 그대로 전달되지 않는 구조와, 작업 배치·분할을 통해 서로 다른 좌석의 처리를 확장하는 메커니즘을 설명한다. 특정 공연 집중에 따른 병목의 대응을 제시하고, 동일 좌석의 배타적 판단은 자원 추가만으로 병렬화할 수 없음을 구분한다. |
| 3 | 2점에 더해, 선택한 분산 단위에 인기 공연 부하가 몰리는 한계를 분석하고 분산 범위 조정 등 개선의 효과와 제약을 설명한다. 조회를 지연 반영해 분리한다면 최신성 저하와 점유 시 거절의 비용을, 다른 방식이라면 그에 따른 확장 이득과 제약을 비교한다. |
