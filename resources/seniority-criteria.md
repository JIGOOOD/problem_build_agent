# 연차별 루브릭 생성 기준

## Middle

Breadth 80% / Depth 20%

상위 수준의 시스템 설계와 주요 컴포넌트의 기본 동작을 이해하는 데 중점을 둔다. 심층적인 구현 지식이나 복잡한 장애 대응 능력까지 요구하지 않는다.

| Level | 기준 |
|---|---|
| 0 | 핵심 설계 문제를 고려하지 않는다. |
| 1 | 설계 문제를 인식하고 기본적인 해결 방안을 제시하지만, 주요 컴포넌트의 역할이나 처리 흐름을 충분히 설명하지 못한다. |
| 2 | 핵심 요구사항을 충족하는 상위 수준의 설계를 제시하고, 주요 컴포넌트의 역할과 기본적인 동작 흐름을 설명한다. |
| 3 | 2점에 더해, 설계의 대표적인 문제점이나 한계를 이해하고 개선 방안을 설명한다. 단, 심층적인 구현 지식이나 복잡한 장애 대응까지 요구하지 않는다. |

## Senior

Breadth 60% / Depth 40%

상위 수준의 설계를 넘어 구체적인 기술적 메커니즘을 이해하고, 잠재적인 문제를 분석하며, 아키텍처 선택의 근거와 Trade-off를 설명하는 데 중점을 둔다.

| Level | 기준 |
|---|---|
| 0 | 핵심 설계 문제를 고려하지 않는다. |
| 1 | 핵심 요구사항을 충족하는 기본 설계를 제시하지만, 관련된 동시성·장애·병목 등의 문제를 충분히 고려하지 못하거나 구체적인 처리 방안을 설명하지 못한다. |
| 2 | 핵심 요구사항을 충족하는 구체적인 기술적 메커니즘을 설명하고, 해당 설계에서 발생할 수 있는 주요 동시성·장애·병목 문제와 대응 방안을 제시한다. |
| 3 | 2점에 더해, 설계의 주요 한계와 복잡한 상황에서 발생할 수 있는 문제를 분석하고, 기술적 선택에 따른 Trade-off와 선택 근거를 설명한다. |

## 공통 생성 규칙

1. 각 Level은 이전 Level보다 높은 설계 역량을 요구해야 한다.
2. Middle은 문제 인식과 미흡한 해결 시도 → 동작하는 설계 → 대표적인 한계 개선으로 발전한다. Senior는 동작하는 기본 설계 → 구체적인 기술적 메커니즘과 주요 문제 대응 → 해당 설계의 한계·복잡한 상황 분석 및 Trade-off와 선택 근거로 발전한다.
3. 연차에 따라 기술 이름이나 설명 길이만 변경하지 않고, 요구하는 기술적 깊이와 문제 해결 범위를 실질적으로 변경한다.
4. Middle은 기본 설계와 대표적인 문제 해결을, Senior는 구체적인 구현 메커니즘과 심층 분석 및 기술적 의사결정을 중심으로 평가한다.
5. 모든 Criterion에 동시성, 장애, 병목을 일괄적으로 요구하지 않는다. 해당 평가 항목과 관련 있는 문제만 다룬다.
6. 특정 기술 사용 여부보다 요구사항을 충족하는 설계의 타당성을 우선 평가한다.
7. Middle 3점은 2점 설계의 대표적인 한계와 개선 방안을 요구한다. Senior 3점은 2점 설계를 바탕으로 주요 한계·복잡한 상황과 Trade-off를 분석하고 선택 근거를 설명하도록 한다. Senior 2점에서 별도의 한계 분석을 필수로 요구하지 않는다. ‘구체적인 메커니즘’, ‘심층 분석’, ‘Trade-off’라는 표현만으로 난이도를 높이지 않는다. Middle 3점과 Senior 2점의 기술이나 해결 방법을 같게 맞출 필요는 없다.
8. Middle은 핵심 요구를 충족하는 구성요소와 기본 처리 흐름을 평가하되, 복잡한 경합·장애 상황별 처리 메커니즘을 Level 2의 필수 조건으로 요구하지 않는다. Senior는 해당 상황에서 정확성을 보장하는 구체적인 처리 메커니즘과 기술적 판단을 요구한다.
